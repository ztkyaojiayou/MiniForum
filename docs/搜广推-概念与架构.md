# 搜广推 · 搜索 / 广告 / 推荐：业务与系统架构

> 创建：2026-08-28
> 主题：平时常说的"搜广推"到底是什么——三块业务的本质、共享的系统底座、本质区别、以及**本项目（目前只有推荐）在其中的位置与差距**。
> 风格：与《限流与熔断》《分布式系统四件套》一致——讲透机制、给实际例子、对比"没做过 vs 做过的人"。
> 核心一句话：**搜广推 = 一套引擎（数据管道→画像→特征→召回→排序→评估）+ 三个目标函数**（相关性 / 留存 / 变现）。

---

## 0. 一句话全貌

```
搜广推 = 搜索(Search) + 广告(Ad) + 推荐(Recommendation)
       ── 互联网公司三大"靠算法分配流量"的核心业务，俗称"三驾马车"

它们底层是同一套引擎：
  海量内容(item) × 用户(user) × 上下文(context) → 打分 → 排序 → 下发
  共享：数据管道 / 画像 / 特征 / 召回 / 粗排 / 精排 / 重排 / 向量检索 / AB实验
区别只在：① 排序的目标函数不同  ② 物品从哪来不同
```

**为什么总放一起讲**：不是三个独立系统，而是**一套底座 + 三个目标函数**。谁先把底座做扎实，谁就能低摩擦地开出三个业务。

## 1. 三块业务分别是什么（各自讲透）

### 1.1 🔍 搜索（Search）——"用户带着明确意图来"

| 维度 | 搜索 |
|---|---|
| 流量怎么来 | **用户主动来**（有明确 query），需求确定性强 |
| 触发方式 | 有 query：`搜"iPhone 15 评测"` |
| 目标函数 | **相关性是硬约束**（搜不到 = 失败），效率其次 |
| 核心难点 | Query 理解（分词/改写/纠错）、相关性判定、时效（新闻搜索要最新的）、权威性 |
| 指标 | 相关性/点击率、无结果率、首屏满意度 |
| 例子 | Google、百度、淘宝搜索、本项目的 `SearchService` |

**搜索的"成败"是二元的**：搜得准是 100 分、搜不准是 0 分——它不像推荐那样"没推荐好还有别的能看"。用户 query 是明确的，**答非所问就是失败**。这是搜索和推荐最本质的区别。

### 1.2 📺 推荐（Recommendation）——"我主动给你递内容"

| 维度 | 推荐 |
|---|---|
| 流量怎么来 | **系统主动推送**（无 query），需求是"隐式/潜在"的 |
| 触发方式 | 无 query：打开 App → 猜你喜欢 / 信息流 |
| 目标函数 | 用户**长期留存 / 互动 / 时长**（engagement），要"喂饱"且不腻 |
| 核心难点 | 兴趣建模（画像）、探索-利用（冷启动/新内容）、多样性、防信息茧房 |
| 指标 | 留存、DAU、人均时长、互动率、冷启动成功率 |
| 例子 | 抖音/快手信息流、微博热搜推荐、本项目的 `/api/recommend/feed` |

**推荐的"成败"是渐变的**：推荐 10 条里有 3 条喜欢就不错（召回命中率就是这么算的）。它的目标是"让用户刷得停不下来"，而不是"答对一道题"。

### 1.3 💰 广告（Ad）——"在内容和用户之间插一段商业流量"

| 维度 | 广告 |
|---|---|
| 流量怎么来 | **寄生在内容流里**（原生广告），用户"被迫路过" |
| 触发方式 | 无显式需求，但会用**用户画像/搜索/推荐上下文**定向 |
| 目标函数 | **广告主 ROI + 平台收入**：eCPM = CTR × CVR × 出价，**最大化平台收益** |
| 核心难点 | 出价/竞价（GSP 二价）、预算控制、定向/人群包、计费（CPM/CPC/CPA）、**反作弊** |
| 指标 | eCPM、广告收入、广告主 ROI、转化率、点击率 |
| 例子 | 抖音开屏/信息流广告、淘宝直通车、百度竞价排名 |

**广告是纯商业逻辑**：一个流量给谁，取决于"谁出价高 × 谁预估转化高"。它与推荐/搜索的本质区别是**引入了"钱"作为排序变量**——同样一个位置，不只看用户喜不喜欢，还要看广告主愿不愿意为这次曝光付钱。

## 2. 一图对比：三者的本质区别

| 维度 | 搜索 | 推荐 | 广告 |
|---|---|---|---|
| 触发 | 有 query（用户主动） | 无 query（系统主动） | 无 query（混排插入） |
| 目标函数 | 相关性（硬约束） | 长期留存/互动 | eCPM = CTR×CVR×出价 |
| 需求确定性 | 高（明确意图） | 低（潜在兴趣） | 中（靠画像定向） |
| 排序变量 | 相关性 | 兴趣+多样性 | **相关性+出价** |
| 评价 | 搜得准不准 | 留不留得住 | 赚不赚钱 |
| 成败形态 | 二元（答非所问=失败） | 渐变（命中 3/10 即可） | 商业化（ROI 说话） |
| 典型场景 | Google / 淘宝搜索 | 抖音信息流 | 抖音开屏广告 |

**一句话总结**：
```
推荐负责"留人"（把用户留在 App 里）
搜索负责"接住明确需求"（用户想找东西时给对结果）
广告负责"变现"（把流量换成钱）
三者闭环：推荐拉时长 → 广告变现 → 数据喂给三者
```

**现实里三者高度融合**：
- 抖音信息流 = **推荐和广告混排**（推荐给广告位打分，混入内容流）；
- 淘宝 = **搜索 + 推荐 + 广告三合一**（搜"手机" → 直通车广告位 + 自然结果混合）；
- 大厂甚至共用一套召回/精排底座，**只是排序层接不同目标函数**。

## 3. 共享底座：为什么"一套引擎"能支撑三块

```
搜广推共同底座（一个引擎，三个业务复用）
数据管道(行为日志) → 画像/特征 → 召回 → 粗排 → 精排 → 重排 → 混排 → 下发 → 行为回流
   ↑ 同一套        ↑ 三块都跑   ↑ 三块各自的目标函数不同
```

| 底座层 | 做什么 | 三块各自怎么用 |
|---|---|---|
| 数据管道 | 行为日志采集/清洗/落仓 | 搜索点击日志、广告曝光/转化日志共用 |
| 画像/特征 | 用户/物品/上下文特征 | 搜索相关性特征、推荐兴趣、广告定向人群包 |
| 召回 | 海量 item → 千级候选 | 搜索=query→item（倒排/向量）；推荐=兴趣/热度/协同；广告=定向圈人 |
| 粗排 | 千级 → 百级（轻模型） | 三块共用，接各自轻量打分 |
| 精排 | 百级 → 十级（重模型） | **三块的分水岭：目标函数不同** |
| 重排 | 十级 → 下发（打散/规则） | 打散/多样性/商业化约束（广告还有预算/频控） |
| AB/评估 | 分桶实验 + 离线指标 | 搜索 NDCG@K、推荐 AUC/GAUC、广告 eCPM 离线模拟 |

**学习者的核心认知**：搜广推不是"三个独立系统"，而是**一套底座 + 三个目标函数**。谁先把底座做扎实，谁就能低摩擦地开出三个业务。

## 4. 落到本项目（目前只有推荐）

### 4.1 现状对照

| 搜广推 | 本项目现状 | 差距 |
|---|---|---|
| **推荐** ✅ | `RecommendService` 完整漏斗（召回 6 路→排序→重排→冷启动→AB→评估），已完成 profile/feature/graph 三域分层 | 已是标准形态 |
| **搜索** ⚠️ 雏形 | `SearchService` + `SearchIndex`（倒排索引，发帖事件增量）：关键字→标题/内容/标签匹配，最新在前 | 缺 **query 理解**（分词/纠错/改写）、**相关性排序**（现在是"标题命中优先 + 时间倒序"，不是相关度打分）、粗精排分层。是"最简关键词搜索"，不是"搜索系统" |
| **广告** ❌ 无 | 完全没有 | 广告是**另一套商业系统**：出价/竞价、预算、计费、定向、反作弊。和推荐/搜索共享底座但目标函数完全不同 |

### 4.2 已有资产 → 搜广推底座的映射（复用清单）

如果未来要上搜索或广告，**共享底座已备好大半**：

| 底座层 | 已备资产 | 搜索/广告怎么复用 |
|---|---|---|
| 行为数据管道 | `BehaviorLog` + Kafka（prod）+ ClickHouse | 搜索点击日志、广告曝光/转化日志同一套 |
| 画像/特征 | `profile.UserProfileService` + `feature.ItemFeatureService` | 搜索定向、广告人群包直接用画像 |
| 图关系 | `graph.SocialGraphService` | 广告"粉丝定向"、搜索的社交信号 |
| 召回 | 6 路召回 + 并行 | 搜索召回 = query→item（需倒排/向量）；广告召回 = 定向圈人 |
| 向量检索 | 无（ItemCF 为主） | 搜索/广告的语义召回需要 embedding + 向量库（Milvus/FAISS）——**这是搜广推都缺的一块** |
| AB/评估 | `AbExperimentService` + `OfflineEvaluator` | 搜索相关性评估（NDCG@K）、广告离线 eCPM 模拟 |

### 4.3 最缺的三块（按优先级）

1. **向量检索**（语义召回）：搜广推三者都缺。搜索靠倒排（本项目已有）只能字面匹配，语义召回要 embedding；推荐从 ItemCF（协同）演进到向量；广告人群定向也要向量。
2. **搜索的 query 理解 + 相关性排序**：把"最简关键词搜索"升级为"搜索系统"——分词/纠错、query 改写、相关度打分（BM25 → 深度相关模型）、NDCG 评估。
3. **广告的商业层**：出价/竞价/预算/计费/反作弊——和推荐/搜索共享底座，但这是另一套商业逻辑（目标函数引入"钱"）。

## 5. 2026 时代背景（搜广推的当前趋势）

- **大模型重构**：LLM 做语义召回 / 生成式推荐 / 多模态内容理解（快手"重构万亿流量"方向）；
- **重排技术**：从规则打散 → 深度模型 + 价值重排（"生死判官"），搜广推都受益；
- **平台化**：搜广推算法策略开发平台（携程等）把召回/特征/模型/实验做成统一平台；
- **融合**：推荐/广告混排、搜索/推荐共享底座，边界越来越模糊。

**对学习者的启发**：理解搜广推，本质是理解"**同一套引擎，目标函数不同**"。本项目把推荐这套引擎做透了，未来扩展搜索/广告时——**共享底座复用、目标函数和排序层另接**——就是大厂的演进路径。

## 6. 没做过 vs 做过的人，对搜广推的认知

| 没做过的人会想 | 做过的人会想 |
|---|---|
| "搜广推是三个不同的系统" | "**一套引擎 + 三个目标函数**，底座共享、排序层各接" |
| "搜索就是字符串匹配" | "搜索的命门是 **query 理解 + 相关性**，相关性是硬约束，答非所问=失败" |
| "推荐就是猜用户喜欢啥" | "推荐目标是**长期留存**，要探索-利用、多样性、防茧房，不追求单次命中" |
| "广告就是在内容里插广告" | "广告是**商业系统**：eCPM=CTR×CVR×出价，竞价/预算/计费/反作弊一套商业逻辑" |
| "三块技术栈完全不同" | "**召回/粗排/精排/重排/特征/画像/AB 全共用**，区别只在目标函数和物品来源" |
| "搜广推门槛在于模型" | "门槛在**底座 + 数据闭环**：没底座，模型再好也没数据喂" |
