# MiniForum 第四期需求规划（互动与发现增强）

> 本文档规划 **MiniForum（迷你微博论坛系统）** 的第四期迭代：深度复刻微博的**互动玩法**与**发现能力**。
> 技术栈：Spring Boot 2.7 + Java 17，内存存储（`ConcurrentHashMap`）+ JSON 文件持久化，**不引入任何第三方中间件**（无数据库 / 无 Redis / 无 MQ / 无搜索引擎 / 无 WebSocket），Session 认证。
> 设计原则：全部功能用纯内存 + JSON 实现，每个功能形成完整的前后端闭环。

---

## 一、本期目标

在已完成功能（F1~F15：关注流 / 通知 / 分类 / 热搜 / 三栏布局等）基础上，补齐微博最核心的**互动链路**与**发现体验**：

1. **全文搜索**：顶部搜索框支持搜帖子（标题/内容/标签）与搜用户，纯内存实现；
2. **话题功能**：发帖支持 `#话题#`，点击话题进入聚合页，话题热度并入热搜榜；
3. **转发功能**：一键转发原帖，带转发计数与转发列表，展示原帖摘要；
4. **@提及**：`@用户名` 自动识别，触发站内通知，点击跳转个人主页；
5. **站内私信**：一对一会话，会话列表 + 未读计数 + 聊天页（轮询刷新，不引 WebSocket）；
6. **前端体验**：深色模式切换 + 移动端适配（汉堡菜单 / 底部 Tab）。

## 二、功能详情

### F16 全文搜索

**目标**：顶部导航栏加入搜索框，支持按关键词检索帖子与用户。

| 项 | 设计 |
|----|------|
| 搜索范围 | 帖子：标题 / 内容 / 标签；用户：用户名 / 昵称 |
| 匹配方式 | 大小写不敏感子串匹配（纯内存遍历，不引入搜索引擎） |
| 接口 | `GET /api/search?q=xxx&type=post\|user&page=1&size=10` |
| 前端 | 搜索框下拉联想 + 独立搜索结果页 `search.html`（Tab 切换帖子/用户） |
| 联动 | 搜索词计入热搜热度（搜索行为加权），热词可再次点击搜索 |

**接口设计**

```http
GET /api/search?q=AI&type=post&page=1&size=10
# 返回：PageResult<PostVO>（标题/内容/标签命中的帖子）

GET /api/search?q=tkzou&type=user&page=1&size=10
# 返回：PageResult<UserBriefVO>（用户名/昵称命中的用户）

GET /api/search?q=AI&type=hot
# 记录搜索词热度（可选：搜索联想可基于热搜榜）
```

**技术说明**：不引入 ES/分词器，子串匹配对演示场景足够；搜索历史可选保存在 localStorage。

### F17 话题功能（#话题#）

**目标**：发帖内容中 `#关键词#` 自动识别为话题，形成话题聚合页。

| 项 | 设计 |
|----|------|
| 识别规则 | 正则 `#([^#\s]{1,20})#` 从帖子内容提取话题词，存入 `Post.topics` 字段 |
| 发帖 | `PostCreateDTO` 增加可选 `topics`（或后端自动从内容提取） |
| 聚合页 | `GET /api/posts?topic=xxx` 按话题过滤帖子 |
| 话题榜 | `GET /api/topics` 返回话题 + 帖子数 + 热度（复用热搜热度算法） |
| 前端 | 帖子正文中 `#话题#` 高亮可点击 → 话题聚合视图（首页 tab 或独立页） |
| 联动 | 话题热度并入热搜榜（热搜词来源 = 标签 ∪ 话题） |

**接口设计**

```http
GET /api/posts?topic=AI&page=1&size=10   # 话题聚合（复用 posts 分页）

GET /api/topics?limit=20                  # 话题榜：[{name:"AI", postCount:12, heat:3210}]
```

**数据模型**：`Post` 增加 `List<String> topics`（JSON 序列化，旧数据 null 兼容）；持久化沿用 `data/posts.json`。

### F18 转发功能

**目标**：微博式转发 —— 一条新帖引用原帖，带转发语义。

| 项 | 设计 |
|----|------|
| 数据模型 | `Post` 增加 `Long repostOfId`（为空表示原创帖） |
| 转发动作 | `POST /api/posts/{id}/repost`，生成一条新帖：作者=当前用户、内容=转发语（可空）、`repostOfId`=原帖 |
| 转发计数 | 原帖 `repostCount` 自增；`PostVO` 增加 `repostCount` 与 `originalPost` 摘要（作者/标题/内容前 50 字） |
| 转发列表 | `GET /api/posts/{id}/reposts?page=1` 返回转发了该帖的帖子列表 |
| 前端 | 帖子卡片加「↩️ 转发」按钮；详情页展示「N 人转发」列表；转发帖嵌套展示原帖摘要 |
| 通知联动 | 原帖作者收到「xx 转发了你的帖子」通知（复用 F2 通知体系） |

**接口设计**

```http
POST /api/posts/{id}/repost        # body: {content:"转发语"} → 201 新帖
GET  /api/posts/{id}/reposts       # 转发列表（分页）
# PostVO 新增字段：repostOfId / repostCount / originalPost
```

**数据模型**：`Post` 增加 `Long repostOfId`、`int repostCount`；持久化兼容（旧数据默认 null / 0）。

### F19 @提及

**目标**：发帖/评论中 `@用户名` 自动识别，触发通知并支持跳转。

| 项 | 设计 |
|----|------|
| 识别规则 | 正则 `@([\w\u4e00-\u9fa5]{1,20})` 从内容提取被提及用户名 |
| 存储 | 帖子/评论内容**原样保存**（Markdown 渲染时高亮），另存 `mentions` 列表（可选） |
| 通知联动 | 被提及用户收到「xx 在帖子/评论中提到了你」通知（复用 F2 通知体系，新增 `MENTION` 类型） |
| 前端 | 渲染层将 `@用户名` 转为可点击链接 → 跳转 `/user.html?username=xxx` |

**接口设计**

```http
POST /api/posts          # body 内容含 @username → 自动识别并通知
POST /api/comments       # 同上
# 通知类型新增 MENTION
```

**技术说明**：被提及人不存在时静默忽略；通知去重（同一帖子多次 @ 同一人只通知一次）。

### F20 站内私信

**目标**：用户之间一对一私信会话。

| 项 | 设计 |
|----|------|
| 数据模型 | `Conversation`（id / 双方 userIds / 最近消息时间）+ `Message`（id / conversationId / fromUserId / content / createdAt / readFlag） |
| 接口 | 发起/回复 `POST /api/messages`；会话列表 `GET /api/conversations`；聊天记录 `GET /api/conversations/{id}/messages`；未读数 `GET /api/messages/unread-count` |
| 轮询刷新 | 前端聊天页每 3~5s 轮询拉取新消息（不引入 WebSocket，符合"无第三方中间件"约束） |
| 通知联动 | 收到新私信 → 顶部铃铛角标 +1（复用 F2 未读体系或独立未读数） |
| 前端 | 私信入口（他人主页/个人中心）+ 会话列表页 `messages.html` + 聊天视图 |

**接口设计**

```http
POST /api/messages                       # body: {toUserId, content} → 自动建会话/追加消息
GET  /api/conversations                  # 会话列表（含对方信息、最后一条消息、未读数）
GET  /api/conversations/{id}/messages    # 聊天记录（按时间升序，翻页可选）
GET  /api/messages/unread-count          # 私信未读总数
POST /api/conversations/{id}/read        # 标记会话已读
```

**数据模型**：`Conversation` / `Message` 两个新实体 + 各自 Repository + DataStore 持久化（`data/conversations.json` / `data/messages.json`）。

## 五、风险与说明

| 风险/说明 | 处理 |
|-----------|------|
| 全文搜索无分词/相关性排序 | 纯子串匹配 + 按热度/时间排序，演示场景足够；后续可接入 Lucene（本期不引入） |
| 私信无实时推送 | 前端 3~5s 轮询，符合"无第三方中间件"约束；数据量小，性能无忧 |
| 话题提取冲突 | 正则提取第一个匹配；空话题忽略；与标签（tags）功能并存不冲突 |
| 转发链深度 | 只支持一层转发（转发帖不可再转发，或再转发时以原帖为准），避免链路复杂 |
| @识别误伤 | 仅匹配已存在用户；Markdown 代码块内不强制排除（演示场景可接受） |
