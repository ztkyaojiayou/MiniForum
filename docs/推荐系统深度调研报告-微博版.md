# 主流推荐系统功能与架构深度调研报告

> 调研时间：2026-08-24
> 调研范围：短视频、电商、长视频、音乐、信息流、本地生活六大赛道的主流平台
> 说明：内容综合公开论文/技术博客/业界分享，区分【公开资料佐证】与【业界共识推断】

## 一、平台选型与功能维度对比

### 1.1 调研平台范围

| 赛道 | 代表平台 | 核心场景 |
|------|---------|---------|
| 短视频 | 抖音/TikTok、快手 | 全屏沉浸式信息流 |
| 电商 | 淘宝/天猫、亚马逊、拼多多 | 猜你喜欢、详情页导购 |
| 长视频 | Netflix、YouTube、爱奇艺 | 首页个性化、相关推荐 |
| 音乐 | Spotify、网易云音乐 | 每日推荐、歌单/电台 |
| 信息流 | 今日头条、微博 | 图文/资讯推荐 |
| 本地生活 | 美团、大众点评 | 商家/菜品/外卖推荐 |

### 1.2 各平台核心推荐功能对比

| 功能 | 抖音 | Netflix | 淘宝 | YouTube | Spotify | 今日头条 |
|------|------|---------|------|---------|---------|---------|
| 个性化推荐流 | ✅ 全屏信息流 | ✅ 首页排行 | ✅ 猜你喜欢 | ✅ 首页推荐 | ✅ 每日推荐 | ✅ 信息流 |
| 相似/关联推荐 | ✅ 相似作品 | ✅ 因为你看过 | ✅ 相似/搭配商品 | ✅ 相关视频 | ✅ 相似歌曲 | ✅ 相关资讯 |
| 榜单/热门 | ✅ 热搜榜 | ✅ Top10 | ✅ 热销榜 | ✅ 趋势榜 | ✅ 排行榜 | ✅ 热点榜 |
| 实时兴趣捕捉 | ⭐ 极强（秒级反馈） | 较弱（看完为信号） | ⭐ 强（加购/收藏） | 中 | 中 | 中 |
| 社交/关注关系 | ✅ 关注流+推荐流 | ❌ 无 | ✅ 店铺/达人关注 | ✅ 订阅 | ✅ 关注艺人 | ✅ 关注作者 |
| 冷启动策略 | 兴趣探测+热门兜底 | 品味画像+问卷 | 问卷+热门兜底 | 分类偏好选择 | 口味问卷 | 兴趣标签选择 |

### 1.3 功能设计维度总结

1. **流量分配机制**：短视频/信息流采用"推荐流为主"（抖音推荐流占绝对主导），长视频/电商采用"主动搜索+被动推荐"双入口；
2. **反馈信号差异**：短视频以完播率/互动为强信号（秒级），电商以点击/加购/转化为强信号，长视频以观看时长/完成率为信号；
3. **重排目标差异**：电商需考虑价格带/商家多样性/利润，短视频需考虑沉浸体验/去重，长视频需考虑连续观看；
4. **冷启动差异**：新用户通过问卷/兴趣标签（头条/Spotify）或探索式投放（抖音）完成冷启动；新品通过内容理解+试探曝光完成。

## 二、通用推荐系统架构拆解

### 2.1 多级漏斗（核心范式）

```
                    全量内容库（数亿级）
                         │
              ┌──────────▼──────────┐
              │  召回（Recall）     │  多路召回：协同过滤/双塔向量/规则/热度
              │  千万 → 数千        │  目标：高召回、低延迟
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  粗排（Coarse）     │  向量检索+轻量模型（双塔打分）
              │  数千 → 数百        │  目标：快速过滤，保证精度下限
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  精排（Ranking）    │  深度模型（Wide&Deep/DIN/DeepFM）
              │  数百 → 数十        │  目标：精准预估 CTR/CVR/时长
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  重排（Re-rank）    │  打散/多样性/MMR/DPP/业务约束
              │  数十 → 最终列表    │  目标：体验+商业目标均衡
              └──────────┬──────────┘
                         │
                      用户曝光
```

- 【公开资料佐证】YouTube 2016 年论文《Deep Neural Networks for YouTube Recommendations》明确描述两阶段：候选生成（Candidate Generation）→ 排序（Ranking）；
- 【公开资料佐证】阿里妈妈《Deep Interest Network for Click-Through Rate Prediction》(DIN) 等论文描述了电商场景的多路召回+深度排序；
- 各厂在粗排与精排之间还有"预排序/截断"变体，但多级漏斗是行业共识范式。

### 2.2 三层计算架构

| 层级 | 时效 | 典型计算 | 代表技术 |
|------|------|---------|---------|
| 离线层（Offline） | 天级/T+1 | 特征统计、模型训练、向量索引构建 | Hadoop/Spark、TensorFlow/PyTorch、Faiss |
| 近线层（Nearline） | 分钟~小时级 | 实时特征窗口、增量更新、兴趣模型 | Flink/Spark Streaming、Kafka |
| 在线层（Online） | 毫秒级 | 实时特征拼接、模型推理、AB打分 | 特征服务、TF Serving/自研推理引擎 |

- 【公开资料佐证】阿里使用 Flink 做实时计算（Flink Forward 大会多次分享），抖音/头条系使用自研实时特征平台；
- 关键点：模型参数周期更新（天级）+ 特征实时计算（秒级）相结合，兼顾精度与时效。

### 2.3 特征平台

1. **特征分层**：用户特征（静态画像/动态兴趣）、物品特征（内容标签/质量分）、上下文特征（时间/场景/设备）、交叉特征；
2. **特征存储**：在线 KV（Redis/自研）、离线 Hive/ODPS、实时特征窗口（Flink state）；
3. **特征服务**：在线推理时毫秒级聚合特征，需特征一致性与版本管理；
4. **实时特征**：用户最近 N 次点击/曝光/停留，电商加购/收藏等强意图信号。

### 2.4 在线服务架构

```
用户请求 → 网关 → 推荐引擎（串行/并行流水线）
                     ├─ 召回服务（多路并行，统一去重）
                     ├─ 粗排服务
                     ├─ 精排服务（模型推理，特征拼接）
                     ├─ 重排服务（业务规则+多样性算法）
                     └─ 曝光日志回传（实时反馈闭环）
```

- 关键点：全程控制在 100~300ms 内；曝光/点击/转化日志实时回流形成学习闭环；
- 架构上强调"预计算 + 实时计算"结合：热门/榜单类可预计算，个性化部分实时计算。

## 三、分平台架构深挖

### 3.1 抖音 / TikTok（短视频）

**核心功能**
- 全屏沉浸式推荐流（默认首屏即推荐），用户无需主动选择；
- 关注流与推荐流并存，但推荐流占绝对主导流量；
- 同款/相似作品（BGM、话题、画面相似内容）、热搜榜/热点榜；
- 实时兴趣捕捉：滑动行为即反馈（快速划过=强负信号），秒级更新用户兴趣。

**架构要点**
- 多级漏斗（召回→粗排→精排→重排）+ 实时特征流；
- 用户兴趣模型：短视频兴趣高度动态，依赖"最近 N 条行为"而非长期画像【业界共识推断，字节未公开论文】；
- 特征：完播率、播放时长、点赞/评论/转发/关注转化、滑动速度、重播次数；
- 冷启动：新用户先看热门内容 + 兴趣探测，通过互动快速收敛画像；新视频靠流量池试探。

**独特设计**
1. **流量池机制**【业界共识推断，多篇行业分析佐证】：新视频先进入小流量池（数百曝光），按完播率/互动率/关注转化等指标打分，达标则进入更大流量池，层层递进，实现"赛马"式内容筛选；
2. **去中心化分发**【业界共识】：弱化粉丝量权重，新创作者内容也有爆款机会，激励供给侧生态；
3. **内容标签体系**：视频多维标签（BGM/话题/画面识别/文案语义）+ 用户兴趣标签，构成匹配基础；
4. **热度衰减模型**：内容热度随时间指数衰减，防止旧内容长期霸占流量，保证新鲜度。

**对比参照**：相比 YouTube 以"观看时长"为优化目标，抖音更强调**互动与完播**等综合信号，且实时性要求更高（秒级反馈 vs 分钟级）。

### 3.2 Netflix（长视频·订阅制）

**核心功能**
- 首页"行+卡片"结构：Top10、因为你看过、继续观看、我的片单、每行内个性化排序；
- 无广告、无商业目标干扰，纯优化**会员留存与观看时长**。

**架构演进**【公开资料：Netflix Tech Blog 系列文章】
- 2006 Netflix Prize：SVD/矩阵分解协同过滤（RMSE 优化）——推荐系统里程碑事件；
- 2013 后转向个性化排序（Personalized Ranking）+ 上下文（设备/时段/观看历史）；
- 2016 后全面拥抱深度神经网络：自研深度学习平台（支持大规模在线学习）。

**特征与信号**
- 观看时长/完成度（按百分位归一化，消除时长绝对值偏差）；
- 品味画像（Taste Communities）：将用户聚类到品味群体，缓解数据稀疏；
- 时间衰减：近期行为权重更高。

**架构特点**
- 两级结构：**选行（Row Selection）+ 行内排序（Ranking within Row）**——先生成"行"（如"科幻片"、"因为你看过 X"），再对行内内容排序；
- 目标函数：不直接优化点击，而优化**观看时长与留存**（点击但秒关=负信号）；
- 冷启动：注册时让用户选择感兴趣的类型/影片，快速建立初始画像【公开资料】。

---

### 3.3 YouTube（长视频·流量广告制）

**核心论文**【公开资料：《Deep Neural Networks for YouTube Recommendations》SIGKDD 2016，推荐系统最经典论文之一】

**两阶段架构**
```
候选生成（Candidate Generation，数亿→数百）
  ├─ 深度网络：将用户观看历史映射为用户向量，与视频向量内积打分
  ├─ 本质是双塔/矩阵分解的深度化：用户塔(历史观看+搜索+人口属性) × 视频塔
  └─ 支持多路：相关视频、订阅、搜索等
排序（Ranking，数百→数十）
  ├─ 深度网络，特征：视频/用户/上下文交叉特征 + 近千个特征
  └─ 目标：期望观看时长（Expected Watch Time），非 CTR
```

**关键设计**
- **优化 watch time 而非点击率**【论文原文】：用加权逻辑回归训练，正样本权重=观看时长，使模型近似优化期望观看时长；
- **负样本采样**：从"曝光未点击"中采样（而非全库随机），更贴近真实分布；
- 特征工程：前几小时行为统计、年龄/性别等人口属性、视频 embedding 拼接；
- 在线服务：候选生成数百毫秒级完成，排序输出最终推荐列表。

**冷启动**：新用户注册选择感兴趣频道/分类；新视频依靠内容元数据（标题/描述/标签）+ 试探曝光。

### 3.4 淘宝 / 天猫（电商）【公开资料：阿里系论文+技术分享最丰富】

**核心功能**
- 首页"猜你喜欢"（Feeds 流）、商品详情页"相似/搭配/看了又看"、购物车推荐、"千人千面"；
- 搜索与推荐联动：搜索后详情页推荐与搜索词相关商品；
- 商业化：推荐流内广告混排（阿里妈妈）。

**架构要点**
- **多路召回**：i2i 协同过滤（看了 A 推荐 B）、u2i 双塔向量召回、规则召回（热门/新品/店铺）、实时行为召回；
- **精排**：深度排序模型（见下方模型演进）；
- **重排**：业务约束极强——价格带打散、商家数限制、多样性、新品/爆品配额、广告与自然结果混合排序。

**电商特有要素**
- 目标：CTR×CVR 转化优化、GMV（成交额）最大化；
- 强信号：加购、收藏、加购物车（比点击强得多的意图信号）；
- 约束：价格/库存/商家维度必须纳入排序与重排。

**公开模型技术**
| 模型 | 年份 | 解决的问题 |
|------|------|-----------|
| DIN（Deep Interest Network）| 2017 | 用注意力机制从用户历史行为中提取与当前候选相关的兴趣 |
| DIEN | 2018 | 建模用户兴趣的**时序演化**（GRU + 兴趣抽取）|
| ESMM | 2018 | 解决点击→转化两阶段**样本选择偏差**，联合建模 CTR/CVR |
| SIM | 2020 | 检索式超长行为序列建模（数万级历史行为）|
| MMoE/PLE | 2018/2020 | 多目标（点击/转化/时长/GMV）建模 |

**实时计算**：阿里是 Flink 主要贡献者，实时特征（秒级行为）+ 实时样本回流支撑在线学习【公开资料：Flink Forward / 阿里技术分享】。

### 3.5 Spotify / 网易云音乐（音乐）

- **Discover Weekly**（每周一更新的个性化歌单）是音乐推荐标杆功能【公开资料：Spotify 技术博客】；
- 音乐推荐核心：**协同过滤 + 音频内容分析**（Spotify 收购 Echo Nest 获得音频指纹/内容标签能力）+ 会话上下文；
- 网易云音乐：**歌单文化**驱动的推荐（歌单即天然的用户兴趣簇），每日推荐 + 私人雷达，评论/收藏强反馈；
- 特点：音乐消费短平快，会话型推荐（根据当前播放列表推荐下一首）比静态列表更重要。

### 3.6 今日头条（信息流）

- **算法分发鼻祖**：张一鸣"用算法取代编辑分发"，开创个性化资讯先河【公开资料】；
- 冷启动设计：注册时**选择兴趣分类标签**（用户主动告知）+ 热门内容兜底；
- 信号：点击、阅读时长、文章完读、划走速度；
- 架构与抖音同源（字节统一推荐中台），多级漏斗 + 实时特征是共同底座。

## 四、方法论沉淀

### 4.1 评估指标体系

**离线指标**（模型迭代阶段）
| 指标 | 含义 | 说明 |
|------|------|------|
| AUC | 排序能力 | 全局排序质量，但对样本不均衡敏感 |
| GAUC | 用户级 AUC | 阿里提出，按用户分组计算加权 AUC，更能反映推荐质量 |
| Recall@K / HitRate@K | 召回率 | 召回阶段评估（真实交互是否在 Top-K 中）|
| NDCG / MAP | 排序质量 | 考虑位置权重，精排阶段评估 |
| 多样性/覆盖度 | 生态指标 | 物品覆盖率、列表多样性（NDCG 不覆盖）|

**在线指标**（AB 实验阶段）
- 点击类：CTR、人均点击；
- 转化类：CVR、GMV、成交用户数（电商核心）；
- 时长类：人均时长、完播率、留存（次留/7日/30日）——**留存是长期价值的终极指标**；
- 生态类：创作者活跃、内容供给多样性。

**关键认知**【业界共识】：离线指标与在线指标相关性弱，离线涨点不等于在线有效，**必须 AB 验证**；单一指标优化容易过拟合（如只优化 CTR 会变成标题党）。

### 4.2 AB 实验体系

- **分层实验框架**：层与层之间正交（互不影响），同层内实验互斥（流量不重叠）；典型分层：召回层/排序层/重排层/策略层；
- **样本量估算**：按最小可检测提升（MDE）与显著性水平计算所需流量与时长，避免过早下结论；
- **常见陷阱**：
  - 辛普森悖论：未按用户分组比较，全局指标被混杂因素误导；
  - 网络效应：社交类产品实验存在溢出效应，需隔离网络层；
  - 时长/留存类指标长尾：需要更长观察窗口；
  - 学习效应：新策略短期增益可能是用户新鲜感，需观察衰减。

### 4.3 冷启动策略

**用户冷启动**
1. 主动收集：注册问卷/兴趣标签（今日头条、Spotify 口味问卷）；
2. 兜底策略：热门内容/编辑精选兜底，保证首屏体验；
3. 探索-利用（EE）平衡：UCB、Thompson Sampling、Epsilon-Greedy 等算法，用小比例流量探索新兴趣；
4. 少样本快速建模：用人口属性/设备/地域等粗粒度特征冷启动，行为积累后平滑过渡到个性化模型。

**物品冷启动**
1. 内容理解：文本（标题/摘要）、视觉（封面/画面）、音频（BGM）标签化，映射到已有内容空间；
2. 图增强：基于知识图谱/行为关系图，用相邻物品特征补全新物品向量（如 PinSage 思路）；
3. 试探曝光：给新品小流量曝光，按反馈信号快速决定是否加量（对应抖音流量池机制）。

### 4.4 排序模型演进路线【公开论文时间线】

```
LR（逻辑回归，2010s 初）        ← 特征工程天花板，需人工交叉
  ↓
FM/FFM（2010/2016）             ← 自动二阶特征交叉
  ↓
Wide&Deep（2016，Google）        ← 记忆（wide）+ 泛化（deep）并行
  ↓
DeepFM（2017，华为）             ← FM 与 DNN 融合，端到端
  ↓
DIN（2017，阿里）                ← 注意力机制，用户行为序列
  ↓
DIEN（2018，阿里）               ← 兴趣演化（GRU）
  ↓
ESMM（2018，阿里）               ← 多阶段（CTR/CVR）联合建模
  ↓
双塔召回（2019，大规模向量检索）  ← 召回侧：Faiss/向量引擎
  ↓
MMoE/PLE（2018/2020）            ← 多目标建模
  ↓
SIM（2020，阿里）                ← 超长行为序列检索式建模
  ↓
图神经网络（PinSage 2018 等）     ← 物品/关系理解
  ↓
LLM 时代（2023+）                ← 大模型语义理解、生成式推荐、Agent 推荐
```

**演进逻辑总结**：特征交叉（LR→FM→DeepFM）→ 用户兴趣建模（DIN/DIEN/SIM）→ 多目标与多阶段（ESMM/MMoE）→ 召回侧向量化（双塔+ANN 检索）→ 内容理解增强（图/GNN/LLM）。

### 4.5 业界关键实践

- **多目标融合**：MMoE/PLE 共享专家网络；线上加权和需调权（CTR×时长×转化）；
- **位置偏差**：排序模型显式建模曝光位置（position bias），训练时用曝光日志+IPW 修正；
- **延迟转化**：电商 CVR 需考虑转化延迟（下单可能数天后），用延迟反馈建模；
- **多样性保障**：MMR（最大边际相关）、DPP（行列式点过程）、类别打散；
- **实时性**：秒级反馈（抖音滑动）与分钟级特征（Flink 流计算）决定推荐质量上限。

## 五、总结与启示

### 5.1 共性架构（可复用的行业范式）

无论哪个平台，成熟推荐系统都收敛到同一套范式：

1. **多级漏斗**：召回（全量→数千）→ 粗排（→数百）→ 精排（→数十）→ 重排（→最终列表），用算力分层换取"精度×延迟"的平衡；
2. **三层计算**：离线（天级训练/索引）+ 近线（分钟级特征）+ 在线（毫秒级推理）协同；
3. **实时反馈闭环**：曝光→行为→日志→特征→模型→下一次推荐的完整回路；
4. **多目标与业务约束**：纯模型精度（CTR/时长）之上叠加多样性、打散、商业规则。

### 5.2 平台差异化（架构随业务目标而变）

| 维度 | 短视频（抖音） | 电商（淘宝） | 长视频（Netflix/YouTube） |
|------|--------------|-------------|--------------------------|
| 核心目标 | 完播+互动+时长 | 点击→转化→GMV | 观看时长/留存 |
| 最强信号 | 秒级滑动/完播 | 加购/收藏/转化 | 完成度/持续观看 |
| 重排重点 | 沉浸感/去重 | 价格带/商家/广告 | 连续观看/避免重复 |
| 实时性要求 | 最高（秒级） | 高（分钟级） | 中（分钟~小时级） |
| 公开程度 | 低（字节保密） | 高（阿里论文多） | 高（Netflix/YouTube 论文） |

### 5.3 对自建推荐系统的启示

1. **先业务目标后技术选型**：明确优化指标（时长/转化/留存）决定整个管线设计；
2. **从简单到复杂**：冷启动阶段用规则+热度兜底，再逐步引入双塔召回→精排模型→多目标；
3. **多级漏斗不可跳过**：直接全量精排在大数据量下不可行，漏斗是规模化必经之路；
4. **数据闭环优先于模型创新**：日志回传、特征一致性、AB 平台是比模型更重要、更早要做的基建；
5. **参考论文图谱**：从 YouTube 2016（管线）、DIN/DIEN（兴趣建模）、ESMM（多阶段）、双塔召回（召回向量化）、MMoE（多目标）按需取用。
