# 阿里开发手册合规整改清单（工程架构审计）

> 创建：2026-09-01
> 依据：《阿里巴巴Java开发手册》编程规约 / 异常日志 / MySQL / 工程 / 设计 各章。
> 方法：三路并行审计（并发·集合·资源 / 异常·日志·分层 / MySQL·设计原则），逐点对照源码核实，给出 文件:行号 + 建议。
> 使用：按 P0 → P1 → P2 逐项整改，完成一项把 `[ ]` 勾成 `[x]` 并注明 commit。
> 定位：本清单是"合规整改"，与 `docs/高并发优化落地清单-带优先级.md`（性能优化）互补——一个是"做对"，一个是"做快"。

---

## 一、优先级总览

| 优先级 | 目标 | 项数 | 说明 |
|---|---|---|---|
| **P0** | 安全 / 正确性（几行改动） | 8 | 密码泄露、并发丢计数、重复插入、零事务、无兜底异常 |
| **P1** | 健壮性 / 性能（中等改动） | 12 | 日志丢堆栈、SELECT *、索引缺失、内存分页、线程池、魔法数 |
| **P2** | 架构级（需设计） | 6 | 上帝类、依赖过重、连接池、锁内 I/O、N+1、注入方式 |

**推荐顺序**：P0 一次 commit 可做 2~3 项（安全正确性优先）→ P1 按"性能痛点"挑 → P2 结合未来拆分一并做。

## 二、🔴 P0 立即修（安全 / 正确性）

- [x] **1. Controller/Service 返回 User 实体，password 哈希泄漏给前端**（✅ commit `cb29adb`）
  - 位置：`UserController.java:52/61/79/86/95`、`UserService.java:38/50/56/73/77/94`、`AuthService.java:54`
  - 问题：`Result<User>` 直接序列化含 `password`（bcrypt 哈希）与 `email`，密码散列暴露给客户端。
  - 建议：Service 返回 `UserVO`（不含密码），Controller 只回 VO。
  - 实做：新增 `dto/response/UserVO`（不含 password），`UserService`/`AuthService.login`/`UserController`/`AuthController` 只回 VO，实体不再越过服务边界；**未用 `@JsonIgnore` 兜底**——`DataStore` 用同一 ObjectMapper 把 `User` 落盘到 `users.json`，加 `@JsonIgnore` 会连密码一起抹掉、重启全站无法登录（脱敏限定在边界层）。`email` 保留（与 `ProfileVO` 一致，管理端需展示）。

- [ ] **2. 点赞/浏览计数读-改-写非原子（并发丢计数）**（补：发现更严重 bug——like/unlike 从不 `postRepository.save()`，prod 计数不落库，随本项一并修）
  - 位置：`PostService.java:599`（`post.setLikeCount(post.getLikeCount()+1)`）、`:617`（-1）、`:269`（viewCount+1）
  - 问题：`getPostOrThrow` 返回共享同一 Post 引用，并发读 N→写 N+1 丢更新；prod 脏对象会落库。
  - 建议：计数改 `AtomicInteger`/`LongAdder` 并 `getAndIncrement`；MySQL 侧 `UPDATE posts SET like_count=like_count+1 WHERE id=?` 原子自增。
  - 实做修正：不用实体改 `AtomicInteger`（波及 Jackson 落盘 + MySql `ResultSet.getLong` 映射），改 Repository 层原子增量 `PostRepository.incrementLikeCount/incrementViewCount`（InMemory `computeIfPresent` / MySql `UPDATE ... SET like_count=like_count+?` + 回读），顺带修复 like/unlike 不落库。✅ commit 见 Commit 2。

- [ ] **3. 点赞 check-then-act 可重复插入**（补：prod `likes` 表已有 `uk_like (post_id, username)`，只需补 InMemory 判重原子化 + `DuplicateKeyException` 兜底）
  - 位置：`PostService.java:591`（`findByPostIdAndUsername(...).isPresent()` 后 `save`）
  - 问题：同用户并发点赞可同时通过判重插入两条 Like（InMemory 无约束、prod likes 表也无唯一索引）。
  - 建议：`likes(post_id, username)` 加唯一索引 + 捕获 `DuplicateKeyException`；InMemory 版用 `putIfAbsent` 语义去重。
  - 实做修正：prod 索引已存在（`MySqlLikeRepository.java:46`）；改为 `LikeRepository.trySaveIfAbsent`（InMemory `putIfAbsent` / MySql 纯 INSERT + catch `DuplicateKeyException`）。✅ commit 见 Commit 2。

- [ ] **4. BehaviorEventQueue.history 无界累积（内存泄漏）**
  - 位置：`forum-core/.../stream/BehaviorEventQueue.java:22/26`
  - 问题：对每条行为事件 `history.add` 无限追加，长跑即 OOM；`CopyOnWriteArrayList` 每次 add 是 O(n) 整数组复制。
  - 建议：改有界环形缓冲（`ArrayDeque`+上限 或 `ConcurrentLinkedQueue`+裁剪）；history 仅测试/回放用，生产可禁用。

- [ ] **5. 全库零事务：importAll 是 DELETE+逐行 insert，中途失败=数据清空+半恢复**
  - 位置：全部 10 个 `MySql*Repository.importAll`（如 `MySqlPostRepository.java:124-134`）
  - 问题：无 `@Transactional`，一条一提交；备份/恢复中途失败即丢失。
  - 建议：`importAll` 加 `@Transactional`（或批量 upsert + 事务回滚）。

- [ ] **6. MessageService 会话 check-then-act 竞态（脏数据）**
  - 位置：`MessageService.java:58-59/90-91`（`findByPair` 后 `orElseGet(save)`）
  - 问题：并发下第二个 save 触发 `uk_pair` 冲突走 upsert 但返回新 id，后续 message 写入不存在的 conversation_id。
  - 建议：改为"直接 `INSERT ... ON DUPLICATE KEY UPDATE` 后按 uk 回读 id"。

- [x] **7. GlobalExceptionHandler 无 Exception 兜底**（✅ commit `cb29adb`）
  - 位置：`forum-admin-server/.../exception/GlobalExceptionHandler.java`（清单原写 recommend-server，实测 handler 在 admin-server；demo-runner 扫描 `com.tkzou.miniforum` 已覆盖全站含 recommend）
  - 问题：只处理 5 类业务/参数异常，未预期异常走默认 500、响应体非统一 Result、可能泄露内部信息。
  - 建议：加 `@ExceptionHandler(Exception.class)` 返回 `Result.error(500,...)` + error 日志。
  - 实做：新增 `@ExceptionHandler(Exception.class)` → `log.error("未预期异常", e)` + `Result.error(500, "服务器内部错误，请稍后重试")`（不泄露内部信息）。

- [x] **8. AuthService 硬编码默认口令 admin123**（✅ commit `cb29adb`）
  - 位置：`AuthService.java:19-24`
  - 问题：默认管理员 `admin/admin123` 硬编码在类里，生产初始密码固定是安全隐患。
  - 建议：改 `@Value("${app.admin.password:}")` + 启动时要求覆盖强口令。
  - 实做：`app.admin.username/password/email` 三个 `@Value` 注入；演示 profile 保留开箱即用 admin/admin123，**prod profile 下仍为默认口令 admin123 时 `initDefaultAdmin` 抛 `IllegalStateException` 启动失败**。

## 三、🟠 P1 短中期（健壮性 / 性能）

- [ ] **9. 约 40 处 catch 只记 e.getMessage() 丢堆栈**
  - 位置：Redis/Kafka/ClickHouse/DataStore/OfflineEvalScheduler/RecommendService 全线（`KafkaBehaviorConsumer:84`、`ClickHouseBehaviorStore:99/126/135`、`DataStore:141`、`RecommendService:143` 等）
  - 建议：统一 `log.warn("...", e)`（异常日志必须带堆栈，手册硬性要求）；Kafka 消费者带 `record.offset()`。

- [ ] **10. SELECT * 25+ 处（含 TEXT 大字段、password）**
  - 位置：全部 `MySql*Repository`（`MySqlPostRepository:99/109/114/120`、`MySqlUserRepository:69/74/79` 等）
  - 建议：显式列名；列表查询不取 content/tags/topics/password 大字段。

- [ ] **11. 3 处主路径索引缺失 → 全表扫描**
  - 位置：`MySqlFollowRepository:127`（`WHERE followee_id=?` 只有 uk 左列）、`MySqlConversationRepository:82`（`user_a=? OR user_b=?`）、`MySqlFavoriteRepository:84`（`username=?`）
  - 建议：分别补 `KEY idx_followee(followee_id,created_at)`、`KEY idx_user_b(user_b)`（或拆 union）、`KEY idx_username(username,created_at)`。

- [ ] **12. findAll() 无 LIMIT + 内存分页（生产每页全拉 posts 含 TEXT）**
  - 位置：`PostService` 全部列表/搜索/标签/分类/热榜路径（`getPosts/getMyPosts/search/getAllTags/getHotPosts` 等）
  - 问题：生产 `SELECT * FROM posts` 全表拉进 JVM 再 filter/sort/paginate，等价深分页 + 大 IO。
  - 建议：SQL 端 `LIMIT` + 游标；搜索/标签/分类筛选下推 `WHERE`（**较大改造，单独排期**）。

- [ ] **13. Executors.newFixedThreadPool 无界队列 + 静态不 shutdown**
  - 位置：`RecallService.java:39`
  - 问题：手册点名禁止 Executors；慢通道可致无界队列 OOM；6 与通道数硬编码脱钩。
  - 建议：`new ThreadPoolExecutor(..., new ArrayBlockingQueue<>(N), 命名工厂, CallerRunsPolicy)`；corePoolSize 与 channel 数绑定；注入 Spring Bean + `@PreDestroy shutdown()`。

- [ ] **14. Kafka 消费者裸 new Thread 不 join**
  - 位置：`KafkaBehaviorConsumer.java:69`、`KafkaPostCreatedConsumer.java:64`
  - 问题：裸建线程、`stop()` 不 join，停机时序依赖巧合。
  - 建议：Spring `TaskExecutor`/`ThreadPoolTaskExecutor` 提交；`@PreDestroy` `shutdown()+awaitTermination` 再 close consumer。

- [ ] **15. postCache 缓存可变实体引用 → 读-写竞态**
  - 位置：`PostService.java:112/269`
  - 问题：缓存与仓库同一 Post 引用，like() 原地改字段与读缓存线程竞争，非 volatile 字段可见性差。
  - 建议：缓存前防御性拷贝，或缓存不可变 VO；与 P0-2 的原子化一并修。

- [ ] **16. TrafficPool/PostState 读-改-写非原子、字段无 volatile**
  - 位置：`TrafficPool.java:100-105/121-142`、`PostState.java:18-26`
  - 问题：行为线程原地累加、请求线程 `tierBonus` 并发读，计数丢 + 晋级读到旧 tier。
  - 建议：计数改 `AtomicInteger`/`volatile`；prod 走 `RedisTrafficPoolStore`（HINCRBY/Lua 原子晋级）。

- [ ] **17. 魔法数散落**
  - 位置：`HotSearchService:106/117/152/179`（热度权重/爆沸阈值）、`RuleRankService:150/155/168`（兴趣融合 0.6/0.4、社交 +1/+0.5、解释阈值 1.5/0.1/0.5）、`PostService:292/312/320/365/661`（分页上限 100、话题 5、截断 20）
  - 建议：提常量或并入 `RecConfig`（rankWeight 已有却未用全）/`@Value`。

- [ ] **18. Controller 过厚：直接编排 IdempotencyStore**
  - 位置：`PostController.java:43-73`
  - 问题：幂等 acquire/release/complete 业务逻辑上移 Web 层（手册：Controller 要薄）。
  - 建议：下沉 `PostService.createPost(..., idempotencyKey)`。

- [ ] **19. MySQL 列名驼峰（违反规约 snake_case）**
  - 位置：全部 10 张表（`userId/postId/likeCount/createdAt/...`）
  - 问题：手册要求数据库列名下划线；驼峰列 + JdbcTemplate 手写 SQL 映射易错。
  - 建议：改 `user_id/post_id/like_count/created_at`（**涉及建表+全部 SQL，较大，单独排期**）。

- [ ] **20. 状态/类型 String 裸值**
  - 位置：`Post.STATUS_*`（"DRAFT"/"PUBLISHED"）、`Notification.TYPE_*`（5 个）、`MySqlOutboxStore`（"PENDING"/"DONE"）
  - 建议：枚举化（项目已有 `BehaviorType` 枚举先例），落库仍存 String。

## 四、🟡 P2 架构级（需设计）

- [ ] **21. PostService 上帝类（713 行）**

  - 问题：CRUD+搜索+标签+话题+分类+点赞+转发+@提及+回收站+热榜+多套缓存，单一职责严重违背。
  - 建议：拆 `PostCommandService` / `PostQueryService` / `LikeService` / `RecycleService` / `TagService`（结合 dto/impl 分层一起做）。

  - 位置：`forum-offline-job/pom.xml`
  - 问题：只为复用评估/模型类，连带 Sentinel/Nacos/Kafka/ClickHouse 全量。
  - 建议：把离线评估/ItemCF 构建复用的类下沉 `forum-core`，offline-job 只依赖 core。

- [ ] **23. ClickHouse 无连接池**
  - 位置：`ClickHouseBehaviorStore.java:140`（`DriverManager.getConnection` 逐次建连）
  - 问题：不是泄漏，但每条查询新建 TCP 连接。
  - 建议：`HikariCP`/DataSource 池化，`@PreDestroy` 关闭。

- [ ] **24. RealtimeFeatureWindow.flush 持锁做 I/O**
  - 位置：`RealtimeFeatureWindow.java:70-115`
  - 问题：`synchronized(this)` 内循环 `postRepository.findById`（I/O），锁内耗时操作。
  - 建议：先取快照（`new ArrayList<>(recentEvents)`）释放锁再聚合；flush 无需 `synchronized(this)`（单 @Scheduled 线程）。

- [ ] **25. FollowService N+1 查询**
  - 位置：`FollowService.java:129-135/139-144/161-196`
  - 问题：每个关注/二度 `findById` 一条 SQL。
  - 建议：批量 `IN` 回源或冗余字段。

- [ ] **26. IdProvider 字段注入（@Autowired(required=false)）**
  - 位置：全部 `MySql*Repository`、`InMemory*Repository`（如 `MySqlPostRepository.java:42`）
  - 问题：手册推荐构造器注入；`required=false`+默认值掩盖注入失败。
  - 建议：改构造器注入。

## 五、✅ 合规亮点（确认无需改）

- `@Profile` 双实现干净互斥（InMemory `!prod` / MySql `prod`），无同 profile 双 bean 冲突；
- 模块依赖无环（`core ← admin/recommend ← offline ← demo-runner`），构造器注入为主、无 bean 循环；
- 无 `SimpleDateFormat` 共享（全走 `LocalDateTime`+Jackson jsr310）；
- 无 `System.out` / `printStackTrace` / `+` 拼接进日志（占位符 `{}` 规范）；
- `TtlCache` 单飞、`SearchIndex` DCL+volatile、`HeatAggregator` compute 原子累加——并发写法正确；
- Redis 关注流 `zrevrangeByScore` 游标分页无深翻页；
- 唯一索引 + `ON DUPLICATE KEY UPDATE count=count+1`（热搜原子累加）、`uk_username/uk_pair/uk_keyword` 设计良好；
- 参数校验整体 JSR-303（DTO `@NotBlank/@Size` + Controller `@Valid`）。
