# 互联网 C 端推荐系统学习路线 · 总览与索引

> **读者背景**：电力 IoT 物联网系统开发者，具备分布式系统、数据管道（Kafka/Flink/Hive）、高并发服务、向量检索（Milvus）等工程能力，正在向互联网 C 端推荐系统补齐认知。
>
> **核心信念**：推荐系统本质是**大型系统，不是模型，不是纯算法**。模型只占 20%，剩下 80% 是数据、工程、实验、监控。本路线的每一章都按这个信念组织——模型知识只讲够用，工程和数据讲透。

## 一、学习路线全景图

```
┌─────────────────────────────────────────────────────────────────┐
│                       第1步：埋点 + 数据管道（地基 · 2周）          │
│        没有数据一切免谈：事件模型 → 日志 → Kafka → Flink → 数仓      │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       第2步：样本生产（1周）                        │
│        数据 → 可训练样本：曝光-点击对齐、负采样、position bias 消偏   │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       第3步：特征平台（1~2周）                     │
│        样本 → 特征：离线/实时/请求时三分法，特征服务，一致性保障      │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐

│        特征 → 服务：召回(双塔+ANN) → 粗排 → 精排 → 重排，延迟预算    │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       第5步：AB实验 + 监控（1周）                  │
│        服务 → 验证：分流分层、显著性检验、四类监控闭环               │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       第6步：业务闭环（持续）                       │
│        验证 → 业务：商业化目标、供给运营、冷启动、反馈迭代           │
└─────────────────────────────────────────────────────────────────┘
        （第1步 → 第6步 形成完整闭环，第6步的反馈重新流入第1步的数据）
```

**路线逻辑**：每一步的产出是下一步的输入，串成一条从"原始数据"到"业务价值"的完整链路。这也是推荐系统真实的数据流方向。

## 三、前置知识（开跑前自检）

以下概念建议在进入第1步前已有基本认知，缺的可以边学边补：

| 领域 | 需要掌握 | 已有基础（IoT） |
|------|---------|----------------|
| 分布式系统 | 消息队列、流处理、缓存、RPC | ✅ 强（可直接迁移） |
| 数据工程 | Kafka、Flink、Hive/Spark、数仓分层 | ✅ 强（时序数据玩得多） |
| 高并发服务 | QPS/延迟/可用性、降级熔断 | ✅ 强（老本行） |
| 向量检索 | ANN、Faiss/Milvus、HNSW | ✅ 强（项目已用 Milvus） |
| 机器学习基础 | 特征、模型、过拟合、评估指标 | ⚠️ 中等（建议补） |
| 深度学习基础 | Embedding、DNN、注意力 | ⚠️ 中等（第4步前补） |
| 统计基础 | 显著性检验、置信区间、A/B 实验 | ❌ 弱（第5步前必须补） |
| 商业意识 | CTR/CVR/GMV/留存、多目标权衡 | ❌ 弱（全路线贯穿补） |

**结论**：你的工程底子（前4项）能覆盖路线 60% 的难度；真正要下功夫的是**统计实验（第5步）**和**商业指标体系（第6步）**。

## 四、六份文档内容索引

### 📄 01-埋点与数据管道（地基）
- 核心认知：**没有曝光就没有点击，没有点击就没有样本，没有样本一切免谈**
- 事件模型：事件四要素（who/what/when/where）、场景（scene_id）、事件类型体系
- 曝光-点击关联链：`request_id + item_id + user_id + position` 四元组
- 日志格式规范：公共字段 + 业务字段，JSON/Protobuf
- 埋点 SDK：本地缓存、批量上报、重试、采样
- 服务端日志 vs 客户端日志：为什么服务端下发日志更可信
- Kafka Topic 划分：按事件类型、分区键、原始/清洗/业务三级
- Flink 实时指标：窗口统计、维表关联、乱序处理（水位线）
- 数仓分层：ODS → DWD → DWS → ADS
- IoT 认知补全：设备上报链路已有，缺的是"事件语义 + request_id 关联链"

### 📄 02-样本生产
- 核心认知：**样本是模型的"教材"，教材质量决定模型上限**
- 什么是样本：曝光-点击对、正样本（点击）、负样本（曝光未点击）
- 曝光-点击对齐：join 逻辑、时间窗口、跨天处理、request_id 关联
- 负采样：采样率、全局 vs 分桶、热门降采样、困难负样本
- position bias：位置特征、Shuffle 实验、IPW/ESMM 消偏思想
- 多任务样本：点击/时长/完播/转化多标签
- 样本质量：去重、去噪、时效回放、快照
- IoT 认知补全：把"告警→处置→复现"转成样本的思维

### 📄 03-特征平台
- 核心认知：**特征平台是推荐系统的"供水系统"，承上启下**
- 特征三大类：用户 / 物品 / 上下文
- 三种生产方式：离线批算（T+1）、实时流算（Flink）、请求时计算
- 特征存储：Hive（离线）/ Redis（在线）/ 向量库（召回）
- 特征服务设计：统一取特征 API、版本管理、上线回滚、降级
- 训练/在线一致性：防止离线在线偏差
- 特征监控：分布漂移（PSI）、缺失率、延迟
- IoT 认知补全：设备属性/遥测 ≈ 物品特征 + 实时特征，缺"用户行为特征"

### 📄 04-在线链路
- 核心认知：**在线链路是"用成本换精度"的多级漏斗 + 延迟预算的艺术**
- 请求全流程：接入 → 特征 → 召回 → 粗排 → 精排 → 重排 → 下发
- 延迟预算分配表：200ms 怎么分、并行化设计
- 召回工程：双塔服务、ANN（Faiss/Milvus/HNSW 参数）、多路融合、向量+标量过滤
- 粗排：双塔批量打分、向量批量内积
- 精排：DeepFM/DIN 推理（TF Serving/ONNX）、batch 推理
- 重排：MMR/DPP、打散、疲劳控制、广告插帧
- 缓存/降级/熔断/兜底：高 QPS 保命四件套
- IoT 认知补全：高并发服务是老本行，新增"漏斗 + 模型推理"

### 📄 05-AB实验与监控
- 核心认知：**没有 AB 实验就没有话语权，离线指标只是参考**
- AB 原理：分流、对照组/实验组、显著性检验（p 值/置信区间/样本量）
- 实验平台架构：分层（layer）、正交、哈希分桶、实验管理
- 指标体系：核心指标（CTR/CVR/时长/GMV）+ 护栏指标
- 辛普森悖论、实验污染、增量实验
- 四类监控：业务指标、模型监控（AUC 漂移/PSI）、服务监控、数据监控
- IoT 认知补全：监控告警是强项；AB 实验是全新领域

### 📄 06-业务闭环
- 核心认知：**推荐系统最终为商业指标服务，模型只是手段**
- 商业化目标：广告/会员/电商 → 北极星指标、多目标权衡
- 供给运营：内容生命周期、作者/商家生态、审核、人工干预
- 冷启动：新用户/新物品策略（探索、迁移、bandit）
- 反馈闭环：推荐 → 反馈 → 迭代的指标驱动流程
- 从算法到产品到商业的完整视角
- IoT 认知补全：设备/客户运营与内容运营的类比

## 六、学习方法建议

1. **按模块打通，不按算法书顺序**：每步先看对应文档，再动手做 demo，再回头看文档
2. **每步都要有产出物**：不是"看完"就算完，而是要产出设计文档或可运行代码
3. **用公开数据集做最小闭环**：第1~4步可以用 MovieLens/淘宝数据把链路跑通
4. **善用你的 IoT 底子**：数据管道、高并发、向量检索直接平移，把精力花在"样本/实验/商业"这三个新大陆
5. **先追求"系统能转"，再追求"模型更准"**：一个能跑通全链路、指标可衡量的小系统，胜过 10 个孤立的 SOTA 模型
