# MiniForum 功能迭代规划

> 本文档规划 **MiniForum（迷你微博论坛系统）** 的下一轮迭代功能。
> 项目定位：一个类似微博的轻量博客系统，用于展示 **AI 辅助编程能力**。
> 技术栈：Spring Boot 2.7 + Java 17，内存存储（`ConcurrentHashMap`）+ JSON 文件持久化，无数据库，无前端框架，Session 认证。
> 设计原则：贴合现有轻量架构，简单可落地，每个功能形成完整的前后端闭环。

## 二、迭代功能规划

### 第一梯队：最能体现「微博」灵魂 + AI 编程能力

| 编号 | 功能 | 说明 | 技术亮点（演示时可讲） |
|------|------|------|------------------------|
| F1 | **关注 / 粉丝 + 关注流** | 关注关系表、个人关注/粉丝列表、首页时间线只看关注的人 | 新增关系实体、双向关联、分层改动贯穿 entity → repo → service → controller → 前端 |
| F2 | **消息通知** | 被点赞 / 被评论 / 被关注时生成通知，带未读标记、已读接口 | 事件驱动的联动逻辑，涉及多个 Service 协作，体现 AI 生成跨模块代码的能力 |
| F3 | **个人主页** | 用户资料页：头像、简介、帖子列表、粉丝数、关注数 | 聚合查询 + 新页面，前后端完整闭环 |
| F4 | **阅读量统计 + 热门排行** | 详情页自增 viewCount，支持按热度排序 | 简单实用，可顺带做「热门帖子」接口 |

### 第二梯队：实用增强

| 编号 | 功能 | 说明 |
|------|------|------|
| F5 | **Markdown 渲染** | 发帖支持 Markdown，前端用 marked.js 渲染，后端存原文 |
| F6 | **收藏功能** | 收藏 / 取消收藏 + 我的收藏列表 |
| F7 | **数据看板** | 首页 / 后台统计：总帖子、总用户、总评论、今日新增、点赞总数 |
| F8 | **回收站** | 删除进回收站、可恢复、30 天后自动清理 |
| F9 | **修改密码 / 个人资料** | 登录后修改密码、昵称、头像 |

### 第三梯队：演示包装（不写业务代码，展示价值高）

| 编号 | 功能 | 说明 |
|------|------|------|
| F10 | **测试补齐** | 为新功能编写单元测试，展示 AI 写测试的能力 |
| F11 | **接口文档** | README 维护 API 文档，展示 AI 生成文档能力 |
| F12 | **Dockerfile + 启动脚本** | 一键容器化运行，展示工程化能力 |

## 三、推荐实施顺序

如果只选一轮（4~5 个功能），推荐组合：

```
第一轮（核心闭环）
  F1 关注流 → F2 消息通知 → F3 个人主页 → F4 阅读量统计 → F7 数据看板
```

理由：这组功能有完整的前后端闭环、有多模块协作的联动逻辑（点赞/评论/关注触发通知），
最能讲出「AI 辅助编程」的完整故事。

```
第二轮（实用增强）
  F5 Markdown → F6 收藏 → F8 回收站 → F9 修改资料
```

```
第三轮（演示包装）
  F10 测试补齐 → F11 接口文档 → F12 Dockerfile
```

## 四、实施说明

- 每个功能按 **Entity → Repository → Service → Controller → 前端页面** 的完整链路实现；
- 每个功能实现完成后运行相关测试验证，并更新本文档状态为 ✅；
- 重要：数据持久化沿用现有 JSON 文件方案（`data/*.json`），新增实体需同步接入持久化。
