# 推荐系统设计方案（微博场景适配版）

> 日期：2026-08-24 ｜ 配套调研：[微博推荐调研](./微博推荐调研.md) ｜ 状态：已批准，按里程碑实施

## 一、目标

在 MiniForum（Spring Boot 2.7.18 + Java 17，内存+JSON 持久化，已有发帖/关注/点赞/评论/收藏/转发/热搜/话题/分类/搜索）上赋能**生产级推荐能力**：业务侧为主、弱训练侧（ItemCF + 规则加权 + Thompson bandit，纯 Java 手写）。中间件（Kafka/Flink/Redis/Nacos）按生产形态使用（接口 + 内存实现默认 + `@Profile("prod")` 适配），不实际跑 Docker。

## 二、微博推荐调研核心结论

1. **双流制**：关注流（时间/智能）+ 推荐流（算法个性化），两流共用信号但权重不同。本项目关注流已有，推荐流为新增。
2. **信号权重（微博特有）**：`转发 > 评论 > 点赞 > 收藏 > 浏览`（专利佐证"阅读权重最低"）。与小红书"收藏优先"相反。
3. **热度分是共同地基**：`hot = w1·转发 + w2·评论 + w3·点赞 + w4·收藏 + w5·浏览 × 作者权重 × 时间衰减`。
4. **强时效**：指数衰减半衰期 2~6h，新内容 <1h 基础曝光兜底。
5. **热搜是最大流量入口**：新用户/新内容冷启动以热搜/热门兜底（本项目已有 HotSearchService）。
6. **话题=兴趣载体**：话题召回 + 兴趣画像按话题聚合。
7. **关注/二度关系**：推荐流里"作者=我关注"加分；"我关注的人转发过"更高分。
8. **作者权重**：`log1p(粉丝数)` + 作者历史互动率。
9. **互动率 vs 绝对量并重**：`f_quality = log1p(深度互动/曝光)` 防马太。
10. **负反馈实时生效**、**可解释 reason**、**评估关注互动率/转发率/多样性/时效性**。

## 三、rankScore（弱训练侧可落地）

```
rankScore = ( 0.30·f_interact + 0.20·f_quality + 0.30·f_interest
            + 0.15·f_social  + 0.10·f_author + 0.10·f_hot
            + λ·explore_bonus ) × f_recency(age, half_life≈4h)
```

| 特征 | 实现 | 权重 |
|---|---|---|
| f_interact 互动热度 | `log1p(3·转发 + 2·评论 + 1·点赞 + 1.5·收藏 + 0.02·浏览)` | 0.30 |
| f_quality 互动率 | `log1p(深度互动/max(曝光,1))` | 0.20 |
| f_interest 兴趣匹配 | ItemCF 相似度 + 话题/标签重叠 | 0.30 |
| f_social 关注关系 | `1 + 1.0·(作者=我关注) + 0.5·(关注的人转过)` | 0.15 |
| f_author 作者权重 | `log1p(粉丝数)` + 作者历史互动率 | 0.10 |
| f_hot 热点 | 热搜/热门话题池归一化热度 | 0.10 |
| f_recency 时效 | `exp(-ln2·age_hours/半衰期)`，半衰期≈4h | 乘法 |
| explore_bonus 探索 | Thompson 采样分；λ 随行为量衰减（新用户 0.5~0.8，老用户 0.1） | +λ |

> 关注流配方：social 0.55 提权、interest 降权、half_life≈6h（与已有关注流共用特征库）。

## 四、功能清单与优先级

### P0 后端核心闭环（第一交付）
- **行为采集与日志**：`BehaviorLog` + Repository（照 DataStore 接入 `behavior-log.json`）；`BehaviorLogger` 接口+内存实现；织入 `PostService.like/unlike/getById/repost`、`FavoriteService`、`CommentService`、`SearchService`、`FollowService`；`/api/recommend/track` 记 CLICK/DISLIKE。微博信号权重 REPOST+3/COMMENT+2/FAVORITE+1.5/LIKE+1/CLICK+1/VIEW+0.02/EXPOSE+0。
- **用户画像**：`UserProfileAggregator` 按话题+类目聚合（带时间衰减 0.7×/天）+ 最近交互序列 + 活跃度；`profile.UserProfileService`。
- **ItemCF 离线模型**：深度互动构建 user→items，`sim(i,j)=co[i][j]/√(N(i)N(j))` + 共同话题/标签相似。
- **多路召回+融合**：Hot / Topic / Category / ItemCf / NewItem / Follow 六通道 + `MergeRecallService`（rank 归一化 1/(rank+60) + 加权 + 去重）。
- **规则排序**：微博式 rankScore。
- **重排**：话题/类目连续≤2 打散 + 去重 + MMR。
- **冷启动**：`NewItemPool` + `ThompsonBandit`；新用户=热搜/热门兜底+兴趣试探；新帖=小流量试探。
- **在线编排+接口**：`RecommendService` + `GET /api/recommend/feed`(PageResult\<RecommendPostVO\>) + `RecConfig` 配置中心 + WebConfig 鉴权 + 可解释 reason。

### P1 生产级能力（第二交付）
- **实时特征链路**：`BehaviorEventQueue`(模拟Kafka) + `RealtimeFeatureWindow`(模拟Flink) + `RealtimeFeatureStore`(接口+内存/Redis适配)。
- **AB 实验**：`AbExperimentService`（`floorMod(hash(uid:salt),100)`），feed 按分组走不同配置，行为日志带 expId。
- **离线评估**：`TimeSplitter` + 指标（互动率/AUC/GAUC/Recall@K/NDCG@K/Coverage/Diversity/Freshness）+ `OfflineEvaluator`。
- **详情相关推荐**：`GET /api/recommend/related?postId=`（ItemCF 相似帖）。
- **热搜协同**：热搜词→关联内容进 f_hot。
- **生产适配代码**：`prod/kafka/KafkaBehaviorLogger`、`prod/redis/RedisRealtimeFeatureStore`、`prod/nacos/NacosConfigService`、`prod/flink/FlinkRealtimeWindow`（`@Profile("prod")`）。

### P2 前端+造数+收尾（第三交付）
- index.html 推荐 Tab（微博式推荐理由）；detail.html 相关推荐区；点击打点+不感兴趣；增强 seed 造数；文档+集成测试。
