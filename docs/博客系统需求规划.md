# 博客系统需求规划

> 本文档基于现有 **MiniForum（迷你微博论坛系统）** 项目，规划一系列与博客相关的扩展需求。
> 现有系统为 Spring Boot 2.7 + Java 17，内存存储（`ConcurrentHashMap`），无数据库。
> 所有需求均按「简单、可落地、与现有架构一致」的原则设计，最终目标是将系统演进为一个具备基础能力的轻量博客平台。

---

## 一、需求总览

| 编号 | 需求名称 | 优先级 | 复杂度 | 说明 |
|------|----------|--------|--------|------|
| R1 | 博文详情页 | P0 | 低 | 点击帖子标题进入详情，展示完整正文 |
| R2 | 博文分页浏览 | P0 | 中 | 列表页分页，避免一次性加载全部 |
| R3 | 博文分类/标签 | P1 | 中 | 给帖子打标签，按标签筛选 |
| R4 | 博文搜索 | P1 | 低 | 按标题/内容关键字搜索 |
| R5 | 点赞功能 | P1 | 低 | 帖子点赞 + 取消点赞 |
| R6 | 评论功能 | P1 | 中 | 对帖子发表评论、查看评论列表 |
| R7 | 我的博客主页 | P2 | 中 | 个人主页，展示某人发布的全部文章 |
| R8 | 文章草稿箱 | P2 | 中 | 保存未发布的草稿 |
| R9 | 数据持久化 | P2 | 高 | 引入 JSON 文件/数据库，解决重启丢数据 |

> **优先级说明：** P0 = 最核心，建议先做；P1 = 常用增强；P2 = 进阶完善。

---

## 二、需求详情

### R1 博文详情页

**目标**：当前帖子列表只显示标题，点击后可查看完整内容。

**改动点**：
- 新增接口 `GET /api/posts/{id}` 返回单篇帖子
- 前端新增 `post_detail.html` 详情页
- 帖子列表每项标题变成可点击链接

**验收标准**：
- [ ] 访问 `/api/posts/{id}` 返回指定帖子，不存在返回 404
- [ ] 详情页展示标题、作者、发布时间、完整正文
- [ ] 从列表页可跳转到详情页

---

### R2 博文分页浏览

**目标**：帖子数量增多后，列表支持分页，提升性能和体验。

**改动点**：
- 新增接口 `GET /api/posts?page=1&size=10`，返回 `{list, total, page, size, totalPages}`
- 前端列表页增加上一页/下一页及页码
- 默认每页 10 条，最新在前

**验收标准**：
- [ ] 分页参数校验（page ≥ 1，size 1~50）
- [ ] 返回总条数与总页数
- [ ] 超出范围返回空列表而非报错

---

### R3 博文分类/标签

**目标**：给帖子打标签，支持按标签筛选，方便分类浏览。

**改动点**：
- `Post` 实体增加 `tags` 字段（List<String>）
- 发帖 DTO 增加可选 `tags` 字段
- 新增接口 `GET /api/tags` 返回所有标签及其帖子数
- 新增接口 `GET /api/posts?tag=xxx` 按标签筛选

**验收标准**：
- [x] 发帖时可附带 1~5 个标签，每个不超过 20 字符
- [x] 按标签筛选返回正确结果
- [x] 标签列表展示每个标签对应的帖子数

---

### R4 博文搜索

**目标**：按关键字搜索标题或内容。

**改动点**：
- 新增接口 `GET /api/posts/search?keyword=xxx`
- 标题命中权重高于内容命中
- 关键字为空时返回空结果或全部（建议返回空并提示）

**验收标准**：
- [x] 关键字在标题或内容中命中即返回
- [x] 关键字忽略大小写
- [x] 空关键字返回提示而非报错

---

### R5 点赞功能

**目标**：给喜欢的帖子点赞，可取消。

**改动点**：
- 新增 `Like` 记录（帖子ID + 用户）
- 新增接口 `POST /api/posts/{id}/like` 和 `DELETE /api/posts/{id}/like`
- 帖子返回字段增加 `likeCount` 和 `likedByMe`
- 同一用户对同一帖子只能点赞一次

**验收标准**：
- [x] 点赞后 likeCount +1，再次点赞不重复累加
- [x] 取消点赞后 likeCount -1
- [x] 需登录后才能点赞

---

### R6 评论功能

**目标**：对帖子发表评论并查看评论列表。

**改动点**：
- 新增 `Comment` 实体（帖子ID、作者、内容、时间）
- 新增接口：
  - `POST /api/posts/{id}/comments` 发表评论
  - `GET /api/posts/{id}/comments` 查看评论
  - `DELETE /api/comments/{commentId}` 删除评论（作者本人/管理员）
- 帖子详情接口可附带评论数

**验收标准**：
- [x] 评论内容必填，不超过 500 字符
- [x] 只能对存在的帖子评论
- [x] 非本人不能删除他人评论

---

### R7 我的博客主页

**目标**：个人主页，展示某用户发布的全部文章。

**改动点**：
- 新增接口 `GET /api/users/{id}/posts` 返回该用户全部帖子
- 前端新增 `user_posts.html` 个人主页
- 帖子列表显示作者，可点击进入该作者主页

**验收标准**：
- [ ] 按作者过滤返回正确帖子列表
- [ ] 用户不存在返回 404
- [ ] 支持分页

---

### R8 文章草稿箱

**目标**：未写完的文章可先保存为草稿，稍后继续编辑发布。

**改动点**：
- `Post` 增加 `status` 字段（`DRAFT` / `PUBLISHED`）
- 发帖接口增加 `publish` 布尔参数（默认 true）
- 新增接口：
  - `GET /api/posts?status=DRAFT` 查看自己的草稿
  - `PUT /api/posts/{id}` 更新并发布
- 草稿仅作者本人可见

**验收标准**：
- [ ] 草稿不出现在公开列表
- [ ] 只有作者能查看/修改自己的草稿
- [ ] 草稿可发布，发布后进入公开列表

---

### R9 数据持久化

**目标**：解决重启后数据丢失问题。

**方案选项**（按简单到复杂）：
1. **JSON 文件持久化**（推荐先做）：启动时从 `data/*.json` 加载，定时/退出时保存
2. **H2 内嵌数据库**：引入 `spring-boot-starter-data-jpa` + H2，接近真实数据库，无需安装
3. **MySQL 等外部数据库**：功能最完整，但需要额外配置

**验收标准**：
- [ ] 重启后帖子、用户数据不丢失
- [ ] 至少一种方案落地并验证

---

## 三、建议实施顺序

按「先核心、后增强」的原则推进：

```
第一阶段（P0，让系统更像博客）
  R1 详情页 → R2 分页

第二阶段（P1，常用互动功能）
  R4 搜索 → R5 点赞 → R6 评论 → R3 标签

第三阶段（P2，进阶完善）
  R7 个人主页 → R8 草稿箱 → R9 数据持久化
```

> 💡 **建议**：优先从 **R1 博文详情页 + R2 分页** 开始，改动最小、收益最直观，且是后续所有功能的基础。
