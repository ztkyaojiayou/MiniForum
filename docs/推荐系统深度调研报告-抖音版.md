# 推荐系统深度调研报告 —— 抖音版

> 调研日期：2026-08-25
> 主题：抖音（Douyin）全屏短视频场景的推荐系统架构，并和微博、小红书三方对比。
> 配套：本报告与《微博推荐调研.md》《推荐系统设计方案.md》并列，供 MiniForum 推荐系统演进参考。

## 0. 一句话总览

抖音推荐的本质是**"内容为中心"的中心化算法分发**：全屏沉浸式消费把"完播率/观看时长/重播/快滑"变成最强信号，流量池赛马决定内容生死；微博是"关系为中心"的社交分发（转发 + 热搜兜底）；小红书是"内容+搜索"的种草分发（双列点击 + 收藏长尾）。

**与图文最大的技术分野**：图文推荐优化"点不点"（CTR），短视频优化"**看不看、看多久、划不划走**"——因为全屏下**曝光即播放**，点击率退化为"续看率"，时长/完播成为唯一能实时反映兴趣强度的强信号。

## 1. 抖音推荐架构总览

### 1.1 产品层

| 机制 | 做法 |
|---|---|
| **全屏沉浸** | 一屏一个视频，上滑切下一个（无翻页）；自动播放、默认有声；"屏幕 = 一个消费单元" |
| **入口** | 顶部 关注 / 推荐（默认）/ 同城；推荐为主、关注为子入口（与微博"关注为主"根本分野） |
| **信号体系** | 完播率 > 观看时长/均播 > 重播 > 点赞 > 评论 > 分享 > 关注 > 不感兴趣；**1~2 秒快滑 = 强负反馈** |
| **流量池赛马** | 新视频进小流量池（约 200-500 曝光【推断】）→ 按完播/互动/关注转化**逐级放大**；看相对表现不看粉丝量，**新号也能爆** |
| **负反馈** | 长按 → 不感兴趣 / 减少类似 / 屏蔽作者 / 举报；审核（机器视觉/语音/字幕识别）是推荐前过滤 |
| **商业化** | 信息流广告 = 特型内容同流；直播带货 = "兴趣电商"（内容激发需求） |

### 1.2 技术层

| 机制 | 做法 |
|---|---|
| **排序目标** | 时长/完播为主 + 互动/关注/负反馈多目标；`final_score = Σ wᵢ·E(各目标)` 或 MMoE/PLE 多任务 |
| **期望时长建模** | 把"时长占比"离散分桶（0-20%、…、100%、重播）→ softmax 预测各桶概率 → 取期望时长（规避长视频回归偏差） |
| **内容理解** | 多模态：视觉抽帧 + ASR 语音 + 字幕 OCR + 元数据 + 质量分 + **封面/前 2 秒吸引力单独建模**（播放自动开始，前 2 秒决定去留） |
| **流量池实现** | 保底曝光配额 + 波次放量 + **Wilson 置信区间下界判晋级**（防小样本误判）+ 作者历史做先验 |
| **实时性** | 行为秒级回流、近线 Flink、热点分钟级起量、负反馈尽快吸收 |
| **EE** | 探索配额（2-10%【推断】）+ UCB/Thompson（目标设为完播率）；多样性打散防茧房 |

## 2. 核心机制详解

### 2.1 为什么是时长/完播而非点击

- 全屏信息流**不需要"点击"就能看内容**（曝光即自动播放），点击语义退化为"有没有划走"。
- **负样本形态改变**：图文"没点"是弱负样本；短视频"1~3 秒内滑走"是强负样本，"看完 80% 才滑走"接近正样本。
- 张一鸣公开强调算法本质是"匹配内容与用户、让用户停留更久"——即优化对象从"单次点击"升级为**用户级长期价值（留存 + 总时长）**。
- **多目标联合优化**：时长目标与互动目标冲突（"又臭又长"拉时长但不满意）。解法：①在线加权组合打分（`score = w1·E(时长) + w2·P(完播) + w3·P(点赞)… − w7·P(负反馈)`）；②MMoE/PLE 多任务门控缓解冲突；③以用户级/会话级留存为终极目标。

### 2.2 多路召回

```
用户请求
  ├ 向量召回（双塔 embedding + ANN，Faiss/向量库）
  ├ 兴趣标签召回（用户 tag 分布 → 匹配视频 tag）
  ├ 话题/音乐/挑战召回（互动过的 hashtag/音乐 → 相关视频）
  ├ 热门召回（全局/同城/垂类实时热门）
  ├ 关注召回（关注作者新视频）
  ├ 同城/地理位置召回
  ├ I2I 相似召回（看过的 → 相似视频）
  ├ U2U 协同召回（相似用户的视频）
  ├ 搜索关联召回
  └ 新内容/低曝光保底召回（新鲜度 + 探索配额）
  各路按配额取 Top-K → 合并去重打散 → 精排
```

- 与图文差异：内容表示从"文本 TF-IDF/关键词"升级为**多模态 embedding**；候选规模亿级且每分钟新增（索引需增量）；**停留时长/完播是最强兴趣信号**。
- 代表性工程：YouTube 双塔召回（arXiv:1606.07792）、字节 Deep Retrieval（arXiv:2007.07203，可学习检索结构）。
- 短视频特有：**同素材去重/搬运识别**（同素材不同账号只保留表现最好的一个进候选）。

### 2.3 排序特征

| 特征层 | 来源 |
|---|---|
| 视觉语义 | CNN/ViT 抽帧 → 视觉 embedding、场景分类、画质分 |
| 语音 | ASR 转写 + 情感识别 → 文本 embedding、有无 BGM |
| 字幕/OCR | 内置字幕、画面文字 |
| 元数据 | 标题、话题、音乐、垂类、时长（分桶） |
| 质量分 | 低质/搬运/水印/色情检测 0~1 |
| 作者特征 | 历史表现、粉丝量、垂类 |
| **前 2 秒吸引力** | 封面/开头几帧 embedding（短视频特有） |

**用户行为序列（短视频版）**：观看序列（最近 N 条 id）+ **时长序列**（每条时长占比）+ 交互序列 + **滑走序列**（负反馈）+ 滑动节奏。
**上下文**：时间、网络（WiFi/流量）、设备、**是否静音**（显著影响完播）、地理位置、会话已消费量。

### 2.4 精排模型演进

```
LR → GBDT → FM/FFM → Wide&Deep → DeepFM
    → DIN/DIEN（行为序列注意力/兴趣演化）
    → MMoE/PLE（多目标门控，缓解"时长 vs 点赞"冲突）
    → 多任务 + 序列 + 实时特征 一体化
```

- **DIN**（arXiv:1706.06978）：对候选与历史行为的相似度做注意力加权（"局部激活"兴趣）。
- **DIEN**（arXiv:1809.03672）：DIN + GRU 兴趣演化。
- **MMoE**（arXiv:1708.05122）/ **PLE**（arXiv:2011.00596）：多目标解耦（PLE 论文即短视频场景）。
- **ESMM**（arXiv:1804.07931）：曝光→点击→转化全空间建模（同思想适用于 曝光→完播→互动→关注 漏斗）。
- **YouTube 时长建模**（arXiv:1606.07792）：把观看时长当回归/加权分类目标。

**短视频特殊设计**：时长占比分桶建模、多任务共享底层+分塔、**序列以会话为单位**（短视频兴趣收敛快，最近 1 个会话 10~50 条最有判别力）、相邻视频连续性/类目打散、负反馈显式进模型、多模态特征直接输入。

### 2.5 流量池/赛马的算法实现

流量池不是一个独立模块，而是**"冷启动探索 + 渐进式放量 + 表现评估决策"**的排序策略：

1. **保底曝光配额（探索）**：每条新视频分配最小曝光预算，无论初始打分多低都跑完试探量。
2. **波次放量**：按批次曝光（500 → 3000 → 1w…），每波结束收集完播/互动统计，序贯决策放大或停止。
3. **置信度处理（防抖）**：小样本用 **Wilson 置信区间下界**评估完播率，避免"运气好的一两条"误判爆款：
   ```
   wilson_lower(p̂, n) = (p̂ + z²/2n − z·sqrt(p̂(1−p̂)/n + z²/4n²)) / (1 + z²/n)
   ```
4. **作者历史做先验**：高表现作者新视频给更高初始权重/更大首波池。
5. **与赛马对应**：同话题/同题材候选共享同一波试探流量，按置信区间排序决定谁拿下一波（在线 bandit 的群组版）。
6. **与排序联动**：流量池档位/剩余试探预算作为特征喂给排序，或对"低曝光待试探内容"加权。

### 2.6 时效性 / 新鲜度

- 热点**分钟级起量、小时级见顶、1~2 天衰减**；绝大多数视频 48h 内定生死。
- 手段：`freshness_w = exp(-λ·age_hours)` 指数衰减；新内容 24h 内召回加权；**近期窗口（30min/1h）曝光增速、完播增速、互动增速**作为实时热度特征（"正在起量"强于"历史总量"）；热门音乐/话题/挑战实时捕捉。

### 2.7 实时性（三层架构）

| 层 | 时效 | 职责 |
|---|---|---|
| 在线 Serving | 毫秒 | 请求 → 召回 → 精排 → 重排；特征取自在线特征库（Redis） |
| 近线 Nearline | 秒~分钟 | Flink 行为回流：实时统计、实时特征、增量样本、增量模型、向量索引增量更新 |
| 离线 Offline | 小时~天 | 全量训练、特征平台、离线评估、模型发布 |

关键：**特征一致性**（离线在线对齐，防 training-serving skew）、**增量学习**（每日多轮/在线梯度）、**新视频分钟级进向量索引**。

### 2.8 探索与利用（EE）

- 短视频兴趣**收敛极快**（刷几十条圈定偏好），纯利用会快速进**信息茧房**；兴趣也**易漂移**。
- 手段：显式探索配额（2-10% 流量给低曝光/新内容，ε-greedy 或 UCB/Thompson，目标设为完播率）；`UCB = 完播率 + c·sqrt(ln t / n)`；**多样性作为隐式探索**（类目打散、同作者限流、MMR、兴趣熵约束）；热点/话题带动探索；负反馈快速吸收。

### 2.9 评估

- **离线**：完播 AUC、时长预测误差、点赞 AUC 各自报告（**多目标分开算**）、多样性（覆盖率/熵/长尾占比）、冷启动效率（新内容达标所需曝光量）。
- **在线（终极）**：人均观看时长、次均时长、次日/7 日留存；完播率、平均观看时长占比、重播率、**无效播放率（<2s 滑走占比）**；互动率；负反馈率；新内容曝光占比、冷启动成功视频比例、创作者中腰部占比。
- 铁律：**离线只做初筛，以线上 A/B 为准**。

## 3. 三方对比：抖音 / 微博 / 小红书

| 维度 | 抖音 | 微博 | 小红书 |
|---|---|---|---|
| **内容形态** | 短视频/直播/图文 | 博文（文本+多图/视频/话题） | 图文笔记/视频 |
| **信息流形态** | 全屏单列沉浸式 | 单列卡片式 | 双列瀑布流 |
| **每屏内容数** | 1 | 约 3-8 条 | 约 6-10 张卡片 |
| **消费决策成本** | 极低（划到即播） | 中（扫标题/卡片） | 高（封面+标题，需点进） |
| **核心信号** | **完播/观看时长/重播 > 快滑负反馈** | **转发 > 评论 > 点赞 > 收藏 > 浏览** | **点击率(封面)+收藏 > 赞** |
| **关注权重** | 低（推荐主导） | **高**（关注+转发是核心） | 中（关注 tab 存在） |
| **时效性** | 短（小时~2 天） | **极短**（热搜分钟级） | **长**（月级长尾） |
| **分发逻辑** | 中心化算法**赛马流量池** | 社交传播 + **热搜兜底** | 算法流量池 + **搜索长尾** |
| **冷启动** | 试探性泛曝光 → 完播晋级 | 热点 + 大V 半运营引导 | 兴趣选择 + 搜索意图 |
| **搜索地位** | 中 | 高（热搜+搜索是流量入口） | **极高**（用户当搜索引擎） |
| **作者/粉丝影响** | **低**（去中心化，新号能爆） | 高（大V 强影响） | 中 |
| **内容生命周期** | 短（几天） | 极短（小时级） | 长（月级） |
| **商业化** | 兴趣电商 + 信息流广告 | 热搜广告位 + 粉丝通 | 种草 + 搜索广告 + 薯条 |

### 三种"推荐哲学"一句话

- **抖音**：优化"**看不看、看多久**"（时间型信号）→ 内容为中心，去中心化分发，流量池赛马。
- **微博**：优化"**转不转**"（传播型信号）→ 关系为中心，社交分发 + 热搜集中爆发。
- **小红书**：优化"**点不点、收不收藏**"（决策型信号）→ 内容 + 搜索种草分发，长尾价值。

## 4. 对当前文本社区的可操作借鉴

> 适用对象：MiniForum（微博式文本社区，已有多路召回 / 新鲜度衰减 / MMR / Thompson / 实时特征 / 多目标加权 / 离线评估）。

### 4.1 信号映射（把"时间型信号"加进数据表）

| 抖音信号 | 文本社区等价物 |
|---|---|
| 完播率 | **阅读完成率**（滚动到底 / 正文长度归一化的停留占比） |
| 观看时长 | **阅读时长**（页面停留秒数） |
| 重播 | 收藏 / 再次打开 / 复制文本 |
| 双击点赞 | 点赞 |
| 快滑负反馈 | 扫一眼不点开 / 短停留即离开 |
| 不感兴趣 | 长按/菜单"不感兴趣" |
| 评论文本分析 | 评论关键词 → 兴趣标签 |

**核心动作**：采集"读到底 / 停留秒数"而非只看"有没有赞"——这是迁移完播率的钥匙。文本负信号不如视频精确（无法知道"看到哪一行"），可用视口区域 + 滚动轨迹粗估【推断】。

### 4.2 给新帖建"流量池/赛马"（纯规则可落地，性价比最高）

```
新帖曝光档位: 0 → 50 → 500 → 5000 → 50000
每档统计: 完读率 + 互动率
判晋级: 用 Wilson 置信区间下界与同类基线比较
  达标 → 晋级并扩大曝光配额；未达标 → 降档/停止
排序时: 试探期新帖按档位加权（保证进入曝光），档位越高权重越高
```

- Wilson 下界一行公式防小样本误判（见 2.5），纯 Java 可实现。
- 同时保留**热搜/话题榜**作集中爆发兜底 → 形成"算法赛马（日常）+ 榜单（集中爆发）"双轨。

### 4.3 排序目标"换血"：期望阅读时长 + 多目标加权

```
score(post) =
    α · expectedReadTimeBucket(post)          // 阅读时长分桶(完读/时长目标, YouTube规则版)
  + β · 互动率                                // 互动
  + γ · (0.5 + 0.5·similarity(userRecentSeq, post))  // 序列注意力(简化DIN)
  + δ · freshness(age)                        // exp(-λ·age)
  + ε · realtimeHeat(post)                    // 近1h阅读增速(实时热度)
  + ζ · tierBonus(post)                       // 流量池档位
  − η · negativeScore(user, post)             // 负反馈/举报惩罚
  + θ · UCB(post)                             // 探索加分(低曝光时)
// 最后做类目打散、同作者限流、同素材去重
```

- 规则版多目标 = 各目标分别算分再线性加权（MMoE 融合层的思想）。
- 权重用离线网格搜索 / 线上 A/B 调。

### 4.4 已对齐的（不用改）

- 新鲜度衰减 `exp(-λ·age)` ✅（项目已有 halfLife）
- Thompson bandit 冷启动 ✅（抖音用 UCB/Thompson 做 EE）
- 多样性 MMR 打散 ✅
- 实时特征 ✅、多路召回 ✅、离线评估 ✅

### 4.5 最小落地步骤（建议顺序）

1. **数据回流**：把"阅读时长/停留"从埋点回收（所有后续改造的前提）；
2. **排序目标换血**：CTR → 期望阅读时长分 + 互动加权；
3. **加新鲜度与实时热度特征**（两条特征，改动最小收益最大）；
4. **加流量池**：新帖档位 + Wilson 下界判晋级；
5. **多路召回扩展**：ItemCF 之外加 热门/关注/新帖/标签 四路（已有 6 路，按需补）；
6. **加序列相似度加权**（简化版 DIN）；
7. **加 EE 与多样性打散**（已有 Thompson/MMR，补显式探索配额）；
8. 最后再考虑 LR/FM 浅层模型，或导出特征训练后 Java 加载。
