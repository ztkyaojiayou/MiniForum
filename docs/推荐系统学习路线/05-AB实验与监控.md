# 第5步：AB实验 + 监控（1周）

> **一句话核心认知**：**没有 AB 实验就没有话语权，离线指标只是参考，线上实验才是真理。** 模型好不好、策略行不行，leader 只信实验数据。同时，没有完善的监控，系统哪天坏了你都不知道——监控是推荐系统的"仪表盘"。

---

## 1. 核心概念与原理

### 1.1 为什么 AB 实验是"命根子"

推荐系统的每一次改动（新模型、新特征、新策略）都要回答一个问题：

> **"这个改动真的让业务变好了吗？"**

离线 AUC 高 ≠ 线上好（有偏差、有未建模因素）。唯一可信的验证方式是**线上实验**：

```
把用户随机分成两组：
  A组（对照）：用旧模型/旧策略
  B组（实验）：用新模型/新策略
同一时间、同一流量、只有这一个变量不同
  ↓ 观察核心指标差异是否"统计显著"
  ↓ 显著且正向 → 全量上线；否则 → 回滚
```

### 1.2 核心统计概念

| 概念 | 含义 | 直觉 |
|------|------|------|
| **p 值** | 假设"两组无差异"成立时，看到当前差异的概率 | p < 0.05 通常认为差异显著 |
| **置信区间** | 真实差异的估计范围 | 区间不含 0 → 差异显著 |
| **样本量** | 每组需要的用户数 | 样本太少，差异再大也不可信 |
| **功效（power）** | 真有差异时能检测出来的概率 | 通常要求 80% |
| **显著性水平 α** | 误判"没差异为有差异"的概率 | 通常 0.05 |

**样本量估算**（简化版）：

```
n = (Z_α/2 + Z_β)² × 2 × σ² / δ²
  Z_α/2 = 1.96（95% 置信）
  Z_β   = 0.84（80% 功效）
  σ     = 指标标准差（CTR 近似 sqrt(p(1-p))）
  δ     = 期望检测的最小提升（如 CTR 提升 0.5pp）
```

**直觉**：想要检测的提升越小（δ 小）、指标波动越大（σ 大），需要的样本越多。CTR 基线 5%，想检测 5% 相对提升，每组大约需要几百万曝光。

### 1.3 实验必须满足的前提

1. **随机性**：用户被随机分到各组（哈希分桶）
2. **同时性**：对照和实验同时跑（不能先跑旧再跑新——时间会带来业务变化）
3. **单一变量**：一次实验只改一个东西
4. **充足样本**：按功效计算样本量，跑够时间
5. **无污染**：实验组用户不受其他实验干扰（分层正交解决，见2.1）

## 2. 关键技术细节

### 2.1 实验平台架构

#### 哈希分桶

```
bucket = hash(user_id + experiment_id) % 1000
bucket ∈ [0,100)   → 对照
bucket ∈ [100,200) → 实验
```

**要点**：同一个用户在不同实验里要独立分桶（因为 hash 带 experiment_id），这样才能正交。

#### 分层（Layer）与正交

实验平台解决"多个实验同时跑但互不干扰"的问题：

```
Layer 1（召回实验）:  user_id → hash → bucket
Layer 2（精排实验）:  user_id → hash → bucket（不同的 hash 盐值）
Layer 3（重排实验）:  user_id → hash → bucket
```

**每个 Layer 独立分桶（不同盐值），实验只在自己 Layer 内比较**：
- Layer 之间正交：用户可能在 Layer1 命中召回实验、Layer2 命中精排实验，互不影响
- 同 Layer 的实验用流量划分：这个 Layer 的 10% 给实验 A，10% 给实验 B，互斥

**为什么需要分层**：没有分层的话，两个实验同时跑会互相污染——A 实验的指标变化分不清是 A 的改动还是 B 的改动。

#### 实验管理

```
实验生命周期：
  申请流量 → 参数配置（分层/分桶比例/指标） → 上线
  → 数据监控 → 显著性与否判定 → 全量/回滚/继续
```

**灰度放量**：新模型先 1% 流量 → 看指标 → 5% → 10% → 全量。小流量出问题损失小。

### 2.2 指标体系

| 类型 | 指标 | 说明 |
|------|------|------|
| **核心指标**（决定实验胜负） | CTR、CVR、GMV、人均时长、留存 | 业务北极星指标 |
| **辅助指标** | 互动率、完播率、次留 | 解释核心指标变化的原因 |
| **护栏指标**（不能变差） | 投诉率、卸载率、搜索占比、DAU | 防止"伤体验换指标" |
| **过程指标** | 曝光量、点击量、各漏斗转化 | 定位问题在哪一环 |

**例子**：精排模型实验核心指标 CTR +1.5%（正向），但护栏指标"人均卸载率 +20%"（负向）→ 实验不通过，因为伤了体验。

### 2.3 常见统计陷阱

| 陷阱 | 说明 | 避免 |
|------|------|------|
| **辛普森悖论** | 分组看 A 赢，合并看 B 赢 | 分层分析（按用户群/时段细分看） |
| **实验污染** | 两个实验互相影响（同 Layer 未互斥） | 分层正交 |
| **早停** | 样本不足就下结论 | 按功效算好样本量，跑够再判 |
| **多重比较** | 看 100 个指标总有"显著"的 | 设护栏指标，主指标预注册 |
| **新奇效应** | 新推荐短期点击高（用户新鲜感） | 实验跑够时间（如 2~4 周） |
| **AA 实验** | 对照 vs 对照验证平台无偏差 | 定期跑 AA 实验校准平台 |

**AA 实验很重要**：两组都用旧策略，理论上无差异；如果 AA 实验出了"显著差异"，说明实验平台本身有偏（分桶不均、指标埋点 bug），先修平台再跑实验。

### 2.4 四类监控

| 监控类型 | 监控什么 | 典型指标 | 告警示例 |
|---------|---------|---------|---------|
| **业务指标** | 产品健康度 | CTR、CVR、时长、GMV、DAU | CTR 日环比 -20% |
| **模型监控** | 模型是否失效 | AUC 漂移、特征 PSI、预测分布 | 线上 AUC 周环比 -0.03 |
| **服务监控** | 系统可用性 | 延迟 P99、QPS、错误率、超时率 | P99 > 300ms、错误率 > 1% |
| **数据监控** | 数据链路 | 埋点量、Kafka lag、样本量、特征缺失率 | 曝光量突降 50% |

#### 模型监控的三个层面

```
① 输入监控：特征分布漂移（PSI）、特征缺失率
② 输出监控：预测分数分布（CTR 预测均值）、预测方差
③ 效果监控：线上 CTR/AUC 环比、与离线评估的偏差
```

**模型没有"失效检测"的后果**：特征分布漂移了、模型悄悄退化，业务指标还在涨（可能别的因素撑着），等发现时已经损失几周。

## 3. 工程落地要点

1. **实验平台最小实现**：分桶（hash）+ 配置中心 + 指标报表 + 显著性计算，用现成统计库（scipy statsmodels）就能搭
2. **指标口径统一**：CTR 的定义（曝光口径/点击去重口径）必须在实验和报表里完全一致
3. **实验流量规划**：核心实验分配足够流量（如 10%~20%），小实验给 1%~5%
4. **监控先行**：系统上线第一天就要有监控，不要等出了问题再补
5. **自动化闭环**（进阶）：实验跑够样本 → 自动算显著性 → 自动全量/回滚建议

## 4. IoT 背景认知补全

### 你的底子能平移什么

| IoT 经验 | 平移到 AB + 监控 |
|---------|----------------|
| 监控告警体系（阈值、告警、看板） | **直接复用**，四类监控里服务/数据监控是你的强项 |
| 服务可观测性（延迟/错误率/QPS） | 直接复用 |
| 日志分析 | 直接复用 |

### 你的认知缺口（重点补）

1. **AB 实验是全新领域**：IoT 一般不搞分层实验（设备没法随机分组、不好衡量业务指标）；C 端 AB 是决策的基础设施，统计知识（p 值/置信区间/样本量/功效）必须补。
2. **模型监控是新的**：IoT 模型多为离线批处理，上线后效果不实时反馈；C 端模型在线服务，**AUC 漂移、PSI、预测分布监控**是必修课。
3. **业务指标是新的**：IoT 关注系统可用性（SLA），C 端关注商业指标（CTR/GMV/留存）——监控体系要从"技术视角"扩展到"业务视角"。
4. **AA 实验/辛普森悖论这些统计陷阱**：完全是新概念，但理解了就不难。

## 5. 常见坑与避坑

| # | 坑 | 后果 | 避坑 |
|---|-----|------|------|
| 1 | 样本不够就下结论 | 误判实验胜负 | 先算样本量，跑够再判 |
| 2 | 实验跑太久（新奇效应） | 高估长期效果 | 定时长（2~4周），看趋势 |
| 3 | 同 Layer 两个实验互不互斥 | 结果污染 | 分层正交，同层互斥 |
| 4 | 只看 CTR 不看护栏指标 | 伤体验换指标 | 核心 + 护栏指标体系 |
| 5 | 没有 AA 实验 | 平台有偏不自知 | 定期 AA 校准 |
| 6 | 模型上线不监控 | 悄悄退化没人知道 | 输入/输出/效果三层监控 |
| 7 | 监控只看服务不看数据 | 数据断了（曝光量暴跌）无感知 | 数据监控（埋点量/样本量） |
| 8 | 指标口径不一致 | 实验和报表对不上 | 统一口径定义 |
